% % % % % % ============================================================
% % % % % \begin{abstract}
% % % % % This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian (DoG) operator for structure-energy extraction in lunar imagery. The proposed system integrates a UART-based streaming interface, two parallel separable convolution stages with distinct smoothing kernels, and on-chip BRAM buffers to enable frame-based processing on a resource-constrained Xilinx Artix-7 FPGA. A hardware-software co-design framework is developed in which the FPGA computes the DoG response while a host system performs normalized cross-correlation (NCC) based template matching on the resulting structure-energy maps. The system is evaluated on a multi-region dataset generated from Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel imagery, comprising 1000 augmented variants across 10 spatially distributed diverse lunar highland patches. Results demonstrate the feasibility of the approach for lunar feature matching: regions visually characterized by compact crater-rim structure yield NCC match rates of 73--99\%, while regions whose dominant spatial structure falls outside the kernel passband at 128$\times$128 pixels do not match reliably. The estimated on-chip power (Vivado post-implementation, medium confidence) is 95~mW at a junction temperature of 25.5\textdegree C, with 3.13\% LUT utilization on the target device.
% % % % % \end{abstract}

% % % % % % ============================================================
% % % % % \section{Introduction}

% % % % % Autonomous vision-based navigation is a critical requirement for planetary exploration missions, particularly for tasks such as terrain relative navigation (TRN), hazard detection and avoidance (HDA), and landing-site assessment. Missions such as Chandrayaan-3 have demonstrated the operational need for onboard vision processing under strict real-time and power constraints \cite{lpsc_ch3_hda}. In this setting, feature-based methods remain highly relevant because they offer deterministic behavior, lower computational cost, and better suitability for embedded hardware than many learning-based alternatives.

% % % % % Among gradient-based vision methods, the Difference of Gaussian (DoG) operator is a well-established band-pass filter that suppresses low-frequency intensity variation and high-frequency noise while preserving mid-frequency edge and structural content. It is commonly used as the front-end of scale-space feature detectors such as SIFT \cite{lowe2004distinctive}, SURF \cite{surf2008}, and ASIFT \cite{asift2009}. In this work, however, DoG is not used for keypoint detection. Instead, the magnitude of the DoG response is treated as a structure-energy map and matched directly using normalized cross-correlation (NCC). This makes the pipeline closer to template-based edge-energy matching than to scale-space extrema detection.

% % % % % Field Programmable Gate Arrays (FPGAs) are a natural platform for such a pipeline because they provide spatial parallelism, deterministic latency, and low power consumption. Designing a deployable FPGA accelerator, however, still requires careful co-design of the convolution pipeline, host interface, memory architecture, and evaluation methodology on real imagery. This paper therefore presents a real-time FPGA-based dual-kernel DoG pipeline for lunar structure-energy matching, evaluated on Chandrayaan-2 Terrain Mapping Camera (TMC) imagery.

% % % % % This work makes the following contributions:
% % % % % \begin{itemize}
% % % % %     \item A fully implemented FPGA dual-kernel DoG pipeline on a Xilinx Artix-7 (Basys 3) device using separable 5-tap binomial approximation kernels at two smoothing scales.
% % % % %     \item A UART-based streaming interface at 2 Mbaud enabling frame transfer between a host PC and the FPGA, together with a host-side NCC matching framework on DoG structure-energy maps.
% % % % %     \item Quantitative evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches from Chandrayaan-2 TMC data, along with post-implementation resource and power estimation analysis on the Artix-7 device.
% % % % % \end{itemize}
% % % % % % ============================================================
% % % % % \section{Related Work}


% % % % % Local feature matching methods involve trade-offs among invariance, computational cost, and hardware suitability. SIFT \cite{lowe2004distinctive} uses a Difference of Gaussian (DoG) scale-space to detect extrema and a gradient-based descriptor that is robust to scale, rotation, and illumination changes. SURF \cite{surf2008} accelerates this framework using integral images and a Hessian-based detector, reducing computational cost while retaining strong matching performance. ASIFT \cite{asift2009} extends SIFT to full affine invariance by simulating camera tilt, improving robustness under large viewpoint changes at the cost of significantly higher computation. ORB \cite{orb2011}, a binary descriptor based on oriented FAST keypoints and rotated BRIEF, is substantially faster than SIFT and is attractive for embedded systems, although its invariance is more limited under large scale changes.

% % % % % For orbital imagery acquired from relatively consistent altitudes, the dominant challenges are illumination variation, minor rotation, and noise rather than extreme viewpoint change. In this setting, DoG-based band-pass filtering can provide a lightweight structural representation without requiring full descriptor extraction. The present work therefore uses DoG as a standalone filtering stage and evaluates the resulting structure-energy map directly using NCC.


% % % % % Feature extraction on FPGA platforms has been extensively studied. Gupta \textit{et al.} \cite{fpga_feature_extraction_survey} survey FPGA-based feature extraction architectures and highlight trade-offs in throughput, resource usage, and precision. SIFT-specific FPGA implementations include Yao \textit{et al.} \cite{sift_keypoint_fpga}, who focus on hardware-efficient keypoint extraction, and Reddy \textit{et al.} \cite{sift_detector_cta}, who present a full SIFT detector with optimized convolution pipelines. Parallel FPGA architectures further improve throughput by exploiting spatial concurrency \cite{parallel_sift_fpga}. For DoG filtering specifically, Kim \textit{et al.} \cite{binary_dog_filter} propose an FPGA-optimized implementation. HOG-based descriptors have also been accelerated on FPGA for real-time pedestrian detection \cite{pure_fpga_hog}, illustrating the broader applicability of hardware gradient processing.


% % % % % Vision-based navigation is well established in space missions. Chandrayaan-3 employed computer vision-based hazard detection and avoidance for autonomous landing-site selection \cite{lpsc_ch3_hda}. Feature matching on Chandrayaan-2 imagery has also been investigated to validate classical descriptor approaches in lunar environments \cite{ch2_sift_matching}. The present work complements this literature by providing a low-power FPGA band-pass pipeline evaluated on real Chandrayaan-2 TMC imagery.

% % % % % \section{System Architecture}

% % % % % The proposed system follows a hardware-software co-design philosophy. The FPGA performs all convolution in hardware at deterministic latency, while the host PC manages dataset operations, augmentation, and NCC matching. Fig.~\ref{fig:fpga} illustrates the complete pipeline.

% % % % % \begin{figure}[htbp]
% % % % % \centerline{\includegraphics[width=0.48\textwidth]{images/flowchart_diagram_fpga.png}}
% % % % % \caption{FPGA DoG processing pipeline. Frames are streamed in via UART RX, buffered in input BRAM, processed through two parallel separable convolution paths, and the mapped DoG output is transmitted via UART TX.}
% % % % % \label{fig:fpga}
% % % % % \end{figure}

% % % % % \subsection{FPGA Pipeline}

% % % % % The FPGA pipeline runs on a Xilinx Artix-7 XC7A35T (Basys~3) at 100~MHz and consists of three stages.

% % % % % \subsubsection{Input Interface}
% % % % % A UART receiver (\texttt{uart\_rx}) at 2~Mbaud (50 clocks/bit at 100~MHz) streams 8-bit grayscale pixels from the host. A 0x55 synchronisation byte marks frame boundaries. Received pixels are stored sequentially into a 16~KB dual-port BRAM (\texttt{input\_buffer}), supporting up to 128$\times$128 pixels.

% % % % % \subsubsection{DoG Core (\texttt{dog\_top})}
% % % % % Two independent separable convolution pipelines operate in parallel on the same input BRAM, sharing a read address bus for cycle-accurate synchronisation. Each pipeline (\texttt{gaussian\_blur\_top}) applies a separable 5-tap kernel using:
% % % % % \begin{itemize}
% % % % %     \item A horizontal stage (\texttt{gaussian\_row\_conv}) using a shift-register tap chain.
% % % % %     \item A vertical stage (\texttt{gaussian\_col\_conv}) using four 128-entry line buffers to maintain a five-row sliding window.
% % % % % \end{itemize}

% % % % % The two kernels are 5-tap binomial approximations to Gaussian smoothing at two different smoothing scales:
% % % % % \begin{equation}
% % % % %     \mathbf{k}_1 = \tfrac{1}{16}[1,\, 4,\, 6,\, 4,\, 1]
% % % % %     \label{eq:k1}
% % % % % \end{equation}
% % % % % \begin{equation}
% % % % %     \mathbf{k}_2 = \tfrac{1}{8}[1,\, 2,\, 2,\, 2,\, 1]
% % % % %     \label{eq:k2}
% % % % % \end{equation}

% % % % % These are integer-coefficient binomial approximations, not analytically defined Gaussian kernels with precise $\sigma$ values. $\mathbf{k}_1$ imposes broader smoothing while $\mathbf{k}_2$ imposes less. The structure-energy response is their difference:
% % % % % \begin{equation}
% % % % %     \text{DoG}(x, y) = B_1(x,y) - B_2(x,y)
% % % % %     \label{eq:dog}
% % % % % \end{equation}

% % % % % where $B_1$ and $B_2$ are the outputs of the respective blur stages. The result is a signed 9-bit value; its dynamic range is data-dependent.

% % % % % This design uses the DoG differently from SIFT: rather than searching for signed extrema in a scale-space pyramid, the \emph{magnitude} of $\text{DoG}(x,y)$ is used as a spatial structure-energy map matched via NCC. The system is therefore a hardware band-pass filter whose output encodes local edge and structural energy.

% % % % % Each pipeline uses a three-state FSM (IDLE $\rightarrow$ READ $\rightarrow$ FLUSH) with a latency compensation counter to discard the initial pipeline fill cycles. Image dimensions are passed as runtime 8-bit parameters (\texttt{img\_width}, \texttt{img\_height}), allowing flexible patch sizes without re-synthesis.

% % % % % \subsubsection{Mapping and Output Interface}
% % % % % The signed DoG pixel is mapped to 8-bit unsigned format before transmission:
% % % % % \begin{equation}
% % % % %     p_{\text{out}} = 128 + \left\lfloor \frac{\text{DoG}}{2} \right\rfloor
% % % % %     \label{eq:map}
% % % % % \end{equation}

% % % % % This centres the output at 128 (zero response), preserving sign information for the host. Mapped pixels are written to a second 16~KB output BRAM (\texttt{output\_buffer}). After processing, the top-level FSM transmits a 0x55 sync byte followed by the 16,384-byte output frame via UART TX.

% % % % % The top-level controller (\texttt{top.v}) manages five states:
% % % % % \begin{enumerate}
% % % % %     \item \textbf{S\_WAIT\_SYNC}: Idle; waits for 0x55 from the host.
% % % % %     \item \textbf{S\_RX\_FRAME}: Receives 16,384 pixels into input BRAM.
% % % % %     \item \textbf{S\_PROCESS}: Asserts \texttt{start\_dog}; waits for \texttt{done}.
% % % % %     \item \textbf{S\_TX\_SYNC}: Sends 0x55 back to signal readiness.
% % % % %     \item \textbf{S\_TX\_FRAME}: Streams 16,384 output pixels to the host.
% % % % % \end{enumerate}

% % % % % \subsection{Host Processing Pipeline}

% % % % % The host system (PySerial/OpenCV) handles dataset management, FPGA communication, and NCC matching. For each frame:
% % % % % \begin{enumerate}
% % % % %     \item The frame is resized to 128$\times$128; the sync byte value (0x55) is replaced with 0x54 to prevent false synchronisation.
% % % % %     \item The frame is transmitted to the FPGA; the DoG output is received.
% % % % %     \item The 128-offset bias is removed to recover the signed response; the absolute value is taken to produce a structure-energy magnitude map; Gaussian smoothing and min-max normalisation to $[0,1]$ are applied.
% % % % %     \item NCC is computed against the stored template energy map using \texttt{cv2.matchTemplate} with \texttt{TM\_CCOEFF\_NORMED}.
% % % % %     \item A threshold of 0.5 classifies the result as match or no-match.
% % % % % \end{enumerate}

% % % % % \section{Dataset and Methodology}

% % % % % The dataset is derived from a Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel calibrated browse image with filename \texttt{ch2\_tmc\_ncn\_20240426T0455517041\_b\_brw\_d18.png}, acquired on 26 April 2024 (PDS Product ID: \texttt{ch2\_tmc\_ncn\_20240426T0455517041\_d\_img\_d18}). In the product naming scheme, \texttt{ch2} denotes Chandrayaan-2, \texttt{tmc} is the Terrain Mapping Camera, and \texttt{ncn} designates the nadir-looking camera (distinct from \texttt{ncf} fore and \texttt{nca} aft stereo channels). This strip covers the northern lunar highlands between approximately $41^\circ$N--$61^\circ$N latitude and $26^\circ$E--$28^\circ$E longitude. Data were accessed via the ISRO ISSDC Map Browse portal~\cite{issdc_mapbrowse}, which provides calibrated browse imagery with associated geometry CSV files mapping pixel coordinates to lunar latitude/longitude at approximately 18~m/pixel ground resolution.

% % % % % The strip is visually characterized as crater-rich highland terrain, with impact features well preserved due to the absence of erosional processes~\cite{nasa_craters}. Patches from this strip tend to contain sharp crater rim edges and shadow boundaries at scales visible in the TMC browse imagery.

% % % % % \begin{figure}[htbp]
% % % % % \centerline{\includegraphics[width=0.48\textwidth]{images/mapbrowse.png}}

% % % % % For each region, one template patch (preprocessed with Gaussian blur and min-max normalisation) and 25 transformed frames are generated using sinusoidal rigid-body transforms:
% % % % % \begin{equation}
% % % % %     \theta(t) = 10^\circ \sin(2\pi t),\quad s(t) = 1 + 0.05\cos(2\pi t),\quad t = \tfrac{f}{25}
% % % % % \end{equation}

% % % % % where $\theta$ and $s$ are rotation angle and scale, $f \in [0,24]$ is the frame index. Stochastic Gaussian blur (probability 0.3) and additive noise (probability 0.3, $\sigma=3$) are applied for realism.

% % % % % \subsection{Augmentation Variants}

% % % % % Each of the 25 frames per region is evaluated under four host-side augmentation variants:
% % % % % (1)~\textbf{Original}--frame as generated;
% % % % % (2)~\textbf{Noise}--Gaussian noise ($\sigma=10$) added;
% % % % % (3)~\textbf{Rotated}--additional 8\textdegree\ rotation;
% % % % % (4)~\textbf{Brightness}--scaled by 1.2 with $+10$ offset.
% % % % % This yields $10 \times 25 \times 4 = 1000$ total FPGA inference calls.

% % % % % The design is notably lightweight: 3.13\% LUT utilization confirms the suitability of the Artix-7 35T for this pipeline, with substantial headroom for additional processing stages. BRAM utilization at 18\% accounts for the two 16~KB frame buffers (input and output).

% % % % % \textbf{Regions~1 and~2} (near Aristoteles M and N craters) produce stable high scores (means 0.564, 0.531; match rates 89\%, 73\%). These patches are visually characterized by compact crater rims with strong edge contrast whose spatial scale fits well within the 128-pixel field of view, producing repeatable structure-energy maps across augmentations. The score drop in Region~2 relative to Region~1 is partly attributable to the rotated variant: several rotated frames fall just below 0.5 (minimum 0.413), suggesting that the crater structure in Region~2 is less rotation-tolerant.

% % % % % \textbf{Regions~3 and~4} achieve the highest scores (means 0.654, 0.634; match rates 99\%, 96\%). Their visually multi-directional edge structure produces rich, spatially distinctive energy maps. Region~4 shows one notable outlier (frame~1, rotated, NCC~=~0.325), likely due to the sinusoidal transform bringing the patch boundary into the convolution, but this does not affect the overall match rate.

% % % % % \textbf{Region~0} is the most instructive failure: despite being selected by the texture scorer (high variance + Sobel response at full browse resolution), all 100 variants yield near-zero NCC (max 0.100). The patch is visually flat at 128-pixel scale--an inter-crater floor whose apparent texture at full resolution is fine-grained sub-pixel variation. After downsampling and band-pass filtering, the DoG output is near-uniform and carries no matchable spatial structure.

% % % % % \textbf{Regions~5--9} score 0.185--0.279 mean, consistently below the threshold. Their dominant visual structure (wide crater floors; gradual albedo variation) operates at spatial scales that either exceed the 128-pixel patch width or fall outside the kernel passband. The DoG response contains some edge energy but not enough concentrated in distinctive spatial patterns for reliable NCC matching. This is a scale-mismatch between terrain structure and pipeline parameters--not a hardware failure.

% % % % % \subsection{Separable Convolution: From $O(N^2)$ to $O(N)$}

% % % % % A central architectural decision is the use of separable convolution for the 5-tap kernels. A direct 2D convolution of a kernel of size $N \times N$ requires $O(N^2)$ multiply-accumulate (MAC) operations per output pixel. Since the kernels in~\eqref{eq:k1}--\eqref{eq:k2} are separable (expressible as the outer product of two 1D vectors), the 2D operation decomposes into a horizontal then vertical 1D pass, reducing the cost to $O(2N) = O(N)$ MACs per pixel~\cite{sep_conv_fpga}. For $N=5$, this replaces 25 multiplications with 10--a 2.5$\times$ arithmetic reduction. The hardware benefit extends further: instead of a 2D tap array requiring $N^2$ registers, the design uses a 1D shift register chain (\texttt{gaussian\_row\_conv}) followed by a four-row line buffer (\texttt{gaussian\_col\_conv}). This allows the complete dual-pipeline front-end to fit in just 650 LUTs (3.13\% of the Artix-7 35T) with timing closure at $+2.893$~ns, directly enabling dual-pipeline operation on a resource-constrained device.

% % % % % \subsection{Band-Pass Filtering and Scale Limitations}

% % % % % The pipeline's matching ability is entirely determined by the spatial information surviving two stages of deliberate reduction: band-pass filtering (DoG) followed by spatial integration (NCC). Any terrain whose dominant structure lies outside the kernel passband at 128$\times$128 pixels will produce a near-uniform energy map regardless of visual richness, yielding a near-zero NCC score.

% % % % % The 10 patches were selected to represent diverse highland terrain types--not to cherry-pick easy cases--characterising for which terrain types and scales the pipeline is useful. Compact, high-contrast crater rims (Regions~1--4) align well with the kernel passband. Smooth floors (Region~0), wide-scale structure (Regions~5, 6, 8), and gradually varying terrain (Regions~7, 9) do not. This is a fundamental limitation of single-scale filtering, motivating multi-resolution extension as future work.

% % % % % \subsection{Architectural Tradeoffs and Threshold Sensitivity}

% % % % % The streaming line-buffer approach in \texttt{gaussian\_col\_conv} avoids a second large BRAM but requires sequential single-pass processing: the column stage cannot be restarted mid-frame without flushing all four buffers. UART at 2~Mbaud dominates round-trip latency ($\approx$164~ms); replacing it with SPI, LVDS, or MIPI CSI-2 would reduce transfer time by 1--2 orders of magnitude, enabling video-rate operation. The estimated 95~mW total on-chip power and 25.5\textdegree C estimated junction temperature suggest thermal loading well within bounds, though these values should be validated by hardware measurement.

% % % % % The 0.5 NCC threshold is conservative for Regions~1--2, where multiple near-miss variants score 0.47--0.49, while all failing regions score below 0.28 mean. A threshold of 0.45 would improve recall without meaningful precision loss. An adaptive threshold derived from a local structure-energy confidence estimate would further improve robustness across heterogeneous terrain.

% % % % % % ============================================================
% % % % % \section{Conclusion}

% % % % % This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian operator for structure-energy extraction, implemented on a Xilinx Artix-7 XC7A35T (Basys~3) and evaluated on real Chandrayaan-2 TMC nadir-channel imagery. The design uses separable 5-tap binomial kernels--reducing per-pixel computation from $O(N^2)$ to $O(N)$ MACs--and occupies just 3.13\% of available LUTs with timing closure at $+2.893$~ns WNS and estimated on-chip power of 95~mW (Vivado post-implementation, medium confidence).

% % % % % Evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches demonstrates the feasibility of the approach: regions visually characterized by compact crater-rim structure yield 73--99\% match rates, while regions whose dominant spatial structure falls outside the kernel passband at 128$\times$128 pixels do not match reliably. The results identify a clear scale-mismatch limitation of single-scale DoG filtering and demonstrate that hardware band-pass filtering provides a useful structural signal for lunar image matching in texture-rich terrain.

% % % % % % ============================================================
% % % % % \section{Future Work}

% % % % % The most immediate extension is a multi-scale hierarchy--applying the same pipeline at multiple resolutions--to widen the range of matchable terrain types beyond compact crater rims. Orientation-aware structural descriptors could improve robustness on low-texture highland terrain where NCC is rotation-sensitive.

% % % % % On the hardware side, replacing UART with a high-speed parallel interface (SPI, LVDS, or MIPI CSI-2) would reduce round-trip latency by 1--2 orders of magnitude, enabling video-rate onboard deployment consistent with the space-rated FPGA vision architectures studied in~\cite{fpga_space_vision,space_fpga_cv}. Physical hardware power and resource measurements would validate the Vivado post-implementation estimates. Finally, an adaptive NCC threshold derived from a local structure-energy confidence map could replace the fixed 0.5 threshold, improving classification robustness across the heterogeneous terrain types encountered in lunar highland imagery.

% % % % \begin{abstract}
% % % % This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian (DoG) operator for structure-energy extraction in lunar imagery. The proposed system integrates a UART-based streaming interface, two parallel separable convolution stages with distinct smoothing kernels, and on-chip BRAM buffers to enable frame-based processing on a resource-constrained Xilinx Artix-7 FPGA. A hardware-software co-design framework is developed in which the FPGA computes the DoG response while a host system performs normalized cross-correlation (NCC) based template matching on the resulting structure-energy maps. The system is evaluated on a multi-region dataset generated from Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel imagery, comprising 1000 augmented variants across 10 spatially distributed diverse lunar highland patches. Results demonstrate the feasibility of the approach for lunar feature matching: regions visually characterized by compact crater-rim structure yield NCC match rates of 73--99\%, while regions whose dominant spatial structure falls outside the kernel passband at 128$\times$128 pixels do not match reliably. The estimated on-chip power (Vivado post-implementation, medium confidence) is 95~mW at a junction temperature of 25.5\textdegree C, with 3.13\% LUT utilization on the target device.
% % % % \end{abstract}

% % % % % ============================================================
% % % % \section{Introduction}
% % % % Autonomous vision-based navigation is a critical requirement for planetary exploration missions, particularly for tasks such as terrain relative navigation (TRN), hazard detection and avoidance (HDA), and orbital change detection. Missions such as Chandrayaan-3 have demonstrated the operational need for onboard vision processing under strict real-time and power constraints~\cite{lpsc_ch3_hda}. Embedded FPGA systems have been proposed for space-based vision applications due to their deterministic latency, reconfigurability, and radiation tolerance relative to general-purpose processors~\cite{fpga_space_vision,space_fpga_cv}.
% % % % Among gradient-based vision methods, the Difference of Gaussian (DoG) operator is a well-established band-pass filter that suppresses low-frequency intensity variation and high-frequency noise while preserving mid-frequency edge and structural content. In this work, we use the DoG not for keypoint detection but as a lightweight spatial filtering stage: the magnitude of the DoG response serves directly as a structure-energy map, which is then matched via normalized cross-correlation (NCC). This formulation is closer to template-based edge-energy matching than to scale-space extrema detection.
% % % % FPGAs provide a suitable platform for accelerating such pipelines due to their inherent spatial parallelism and low power consumption. Deploying a practical FPGA DoG accelerator requires careful co-design of the convolution pipeline, host interface, memory architecture, and evaluation methodology on real imagery.
% % % % This work makes the following contributions:
% % % % \begin{itemize}
% % % %     \item A fully implemented FPGA dual-kernel DoG pipeline on a Xilinx Artix-7 (Basys~3) device using separable 5-tap binomial approximation kernels at two smoothing scales, with runtime-configurable image dimensions and post-implementation resource and power estimation analysis on the Artix-7 device.
% % % %     \item A UART-based streaming interface at 2~Mbaud enabling frame transfer between a host PC and the FPGA.
% % % %     \item A hardware-software co-design evaluation framework using NCC-based template matching on the host, with quantitative evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches from Chandrayaan-2 TMC data.
% % % % \end{itemize}
% % % % % ============================================================
% % % % \section{Related Work}
% % % % Classical descriptors such as SIFT~\cite{lowe2004distinctive}, SURF~\cite{surf2008}, ASIFT~\cite{asift2009}, and ORB~\cite{orb2011} trade invariance against computational cost; for orbital imagery from consistent altitudes, simpler band-pass filtering suffices.

% % % % For orbital imagery acquired from consistent altitudes, the primary challenges are illumination variation, minor rotation, and noise rather than large viewpoint change. In this context, DoG-based band-pass filtering provides a hardware-efficient structural signal without requiring full descriptor extraction. The present work uses DoG as a standalone filtering stage--not as part of a SIFT pipeline--and evaluates the structure-energy map directly via NCC.
% % % % Feature extraction on FPGA platforms has been extensively studied. Gupta~\textit{et al.}~\cite{fpga_feature_extraction_survey} survey FPGA-based feature extraction architectures. Nakahara and Sato~\cite{dog_fpga_hw} propose a dedicated hardware architecture for DoG calculation in image feature extraction, directly relevant to this work. SIFT-specific FPGA implementations include Yao~\textit{et al.}~\cite{sift_keypoint_fpga} for hardware-efficient keypoint extraction, Reddy~\textit{et al.}~\cite{sift_detector_cta} for a full SIFT detector, and wearable computing FPGA implementations of SIFT~\cite{sift_fpga_wearable}. Parallel FPGA architectures exploit spatial concurrency for higher throughput~\cite{parallel_sift_fpga}, and FPGA-accelerated oriented-FAST features for SLAM demonstrate the viability of hardware gradient pipelines in real-time navigation~\cite{ofast_dog_fpga}. For DoG filtering specifically, Kim~\textit{et al.}~\cite{binary_dog_filter} propose a fast FPGA-optimised implementation. HOG-based descriptors have also been accelerated on FPGA for pedestrian detection~\cite{pure_fpga_hog}, and Park~\textit{et al.}~\cite{dog_retinex_fpga} demonstrate FPGA-based pixel-level image processing for illumination-invariant feature quality--highlighting the broad applicability of hardware image filtering beyond pure feature detection. A key enabler across many of these implementations is separable convolution: Jamali~\textit{et al.}~\cite{sep_conv_fpga} demonstrate energy-efficient parameterized 2-D separable convolution on FPGA, showing significant resource savings over direct 2-D implementations--a result directly borne out in our design.
% % % % Vision-based navigation is well established in space missions. Chandrayaan-3 employed a computer vision-based HDA system for autonomous landing site selection~\cite{lpsc_ch3_hda}. Feature matching using Chandrayaan-2 data has been studied in~\cite{ch2_sift_matching}, validating classical descriptor approaches on lunar imagery. Liu~\textit{et al.}~\cite{fpga_space_vision} present a run-time reconfigurable MPSoC-based on-board processor for vision-based space navigation, and Thomas~\textit{et al.}~\cite{space_fpga_cv} adapt robotics vision algorithms for space-rated FPGAs, both highlighting the maturity of FPGA-based vision for space deployment.
% % % % The present work complements this literature by providing a low-power, modular FPGA band-pass pipeline evaluated on real Chandrayaan-2 TMC imagery, with explicit analysis of which terrain types benefit from single-scale DoG filtering.
% % % % % ============================================================
% % % % \section{System Architecture}
% % % % The proposed system follows a hardware-software co-design philosophy. The FPGA performs all convolution in hardware at deterministic latency, while the host PC manages dataset operations, augmentation, and NCC matching. Fig.~\ref{fig:fpga} illustrates the complete pipeline.
% % % % \begin{figure}[htbp]
% % % % \centerline{\includegraphics[width=0.48\textwidth]{images/flowchart_diagram_fpga.png}}
% % % % \caption{FPGA DoG processing pipeline. Frames are streamed in via UART RX, buffered in input BRAM, processed through two parallel separable convolution paths, and the mapped DoG output is transmitted via UART TX.}
% % % % \label{fig:fpga}
% % % % \end{figure}
% % % % \subsection{FPGA Pipeline}
% % % % The FPGA pipeline runs on a Xilinx Artix-7 XC7A35T (Basys~3) at 100~MHz and consists of three stages.
% % % % \subsubsection{Input Interface}
% % % % A UART receiver (\texttt{uart\_rx}) at 2~Mbaud (50 clocks/bit at 100~MHz) streams 8-bit grayscale pixels from the host. A 0x55 synchronisation byte marks frame boundaries. Received pixels are stored sequentially into a 16~KB dual-port BRAM (\texttt{input\_buffer}), supporting up to 128$\times$128 pixels.
% % % % \subsubsection{DoG Core (\texttt{dog\_top})}
% % % % Two independent separable convolution pipelines operate in parallel on the same input BRAM, sharing a read address bus for cycle-accurate synchronisation. Each pipeline (\texttt{gaussian\_blur\_top}) applies a separable 5-tap kernel using:
% % % % \begin{itemize}
% % % %     \item A horizontal stage (\texttt{gaussian\_row\_conv}) using a shift-register tap chain.
% % % %     \item A vertical stage (\texttt{gaussian\_col\_conv}) using four 128-entry line buffers to maintain a five-row sliding window.
% % % % \end{itemize}
% % % % The two kernels are 5-tap binomial approximations to Gaussian smoothing at two different smoothing scales:
% % % % \begin{equation}
% % % %     \mathbf{k}_1 = \tfrac{1}{16}[1,\, 4,\, 6,\, 4,\, 1]
% % % %     \label{eq:k1}
% % % % \end{equation}
% % % % \begin{equation}
% % % %     \mathbf{k}_2 = \tfrac{1}{8}[1,\, 2,\, 2,\, 2,\, 1]
% % % %     \label{eq:k2}
% % % % \end{equation}
% % % % These are integer-coefficient binomial approximations, not analytically defined Gaussian kernels with precise $\sigma$ values. $\mathbf{k}_1$ imposes broader smoothing while $\mathbf{k}_2$ imposes less. The structure-energy response is their difference:
% % % % \begin{equation}
% % % %     \text{DoG}(x, y) = B_1(x,y) - B_2(x,y)
% % % %     \label{eq:dog}
% % % % \end{equation}
% % % % where $B_1$ and $B_2$ are the outputs of the respective blur stages. The result is a signed 9-bit value; its dynamic range is data-dependent.
% % % % This design uses the DoG differently from SIFT: rather than searching for signed extrema in a scale-space pyramid, the \emph{magnitude} of $\text{DoG}(x,y)$ is used as a spatial structure-energy map matched via NCC. The system is therefore a hardware band-pass filter whose output encodes local edge and structural energy.
% % % % Each pipeline uses a three-state FSM (IDLE $\rightarrow$ READ $\rightarrow$ FLUSH) with a latency compensation counter to discard the initial pipeline fill cycles. Image dimensions are passed as runtime 8-bit parameters (\texttt{img\_width}, \texttt{img\_height}), allowing flexible patch sizes without re-synthesis.
% % % % \subsubsection{Mapping and Output Interface}
% % % % The signed DoG pixel is mapped to 8-bit unsigned format before transmission:
% % % % \begin{equation}
% % % %     p_{\text{out}} = 128 + \left\lfloor \frac{\text{DoG}}{2} \right\rfloor
% % % %     \label{eq:map}
% % % % \end{equation}
% % % % This centres the output at 128 (zero response), preserving sign information for the host. Mapped pixels are written to a second 16~KB output BRAM (\texttt{output\_buffer}). After processing, the top-level FSM transmits a 0x55 sync byte followed by the 16,384-byte output frame via UART TX.
% % % % The top-level controller (\texttt{top.v}) manages five states:
% % % % \begin{enumerate}
% % % %     \item \textbf{S\_WAIT\_SYNC}: Idle; waits for 0x55 from the host.
% % % %     \item \textbf{S\_RX\_FRAME}: Receives 16,384 pixels into input BRAM.
% % % %     \item \textbf{S\_PROCESS}: Asserts \texttt{start\_dog}; waits for \texttt{done}.
% % % %     \item \textbf{S\_TX\_SYNC}: Sends 0x55 back to signal readiness.
% % % %     \item \textbf{S\_TX\_FRAME}: Streams 16,384 output pixels to the host.
% % % % \end{enumerate}
% % % % \subsection{Host Processing Pipeline}
% % % % The host system (PySerial/OpenCV) handles dataset management, FPGA communication, and NCC matching. For each frame:
% % % % \begin{enumerate}
% % % %     \item The frame is resized to 128$\times$128; the sync byte value (0x55) is replaced with 0x54 to prevent false synchronisation.
% % % %     \item The frame is transmitted to the FPGA; the DoG output is received.
% % % %     \item The 128-offset bias is removed to recover the signed response; the absolute value is taken to produce a structure-energy magnitude map; Gaussian smoothing and min-max normalisation to $[0,1]$ are applied; NCC is then computed against the stored template energy map using \texttt{cv2.matchTemplate} with \texttt{TM\_CCOEFF\_NORMED}.
% % % %     \item A threshold of 0.5 classifies the result as match or no-match.
% % % % \end{enumerate}
% % % % % ============================================================
% % % % \section{Dataset and Methodology}
% % % % The dataset is derived from a Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel calibrated browse image with filename \texttt{ch2\_tmc\_ncn\_20240426T0455517041\_b\_brw\_d18.png}, acquired on 26 April 2024 (PDS Product ID: \texttt{ch2\_tmc\_ncn\_20240426T0455517041\_d\_img\_d18}). In the product naming scheme, \texttt{ch2} denotes Chandrayaan-2, \texttt{tmc} is the Terrain Mapping Camera, and \texttt{ncn} designates the nadir-looking camera (distinct from \texttt{ncf} fore and \texttt{nca} aft stereo channels). This strip covers the northern lunar highlands between approximately $41^\circ$N--$61^\circ$N latitude and $26^\circ$E--$28^\circ$E longitude. Data were accessed via the ISRO ISSDC Map Browse portal~\cite{issdc_mapbrowse}, which provides calibrated browse imagery with associated geometry CSV files mapping pixel coordinates to lunar latitude/longitude at approximately 18~m/pixel ground resolution.
% % % % The strip is visually characterized as crater-rich highland terrain, with impact features well preserved due to the absence of erosional processes~\cite{nasa_craters}. Patches from this strip tend to contain sharp crater rim edges and shadow boundaries at scales visible in the TMC browse imagery.
% % % % \begin{figure}[htbp]
% % % % \centerline{\includegraphics[width=0.48\textwidth]{images/mapbrowse.png}}
% % % % \caption{Chandrayaan-2 TMC browse image accessed via the ISRO ISSDC Map Browse portal. The highlighted strip (\texttt{ncn}, nadir channel) covers the Aristoteles crater neighbourhood in the northern lunar highlands.}
% % % % \label{fig:mapbrowse}
% % % % \end{figure}
% % % % Ten 128$\times$128 pixel patches are extracted using a texture scoring criterion combining pixel variance and mean absolute Sobel gradient magnitude, with a minimum spatial separation of 150 pixels. Geo-referencing uses the accompanying geometry CSV file to map pixel coordinates to lunar latitude/longitude.

% % % % \end{figure}

% % % % For each region, one template patch (preprocessed with Gaussian blur and min-max normalisation) and 25 transformed frames are generated using sinusoidal rigid-body transforms:
% % % % \begin{equation}
% % % %     \theta(t) = 10^\circ \sin(2\pi t),\quad s(t) = 1 + 0.05\cos(2\pi t),\quad t = \tfrac{f}{25}
% % % % \end{equation}
% % % % where $\theta$ and $s$ are rotation angle and scale, $f \in [0,24]$ is the frame index. Stochastic Gaussian blur (probability 0.3) and additive noise (probability 0.3, $\sigma=3$) are applied for realism.

% % % % Each of the 25 frames per region is evaluated under four host-side augmentation variants:
% % % % (1)~\textbf{Original}--frame as generated;
% % % % (2)~\textbf{Noise}--Gaussian noise ($\sigma=10$) added;
% % % % (3)~\textbf{Rotated}--additional 8\textdegree\ rotation;
% % % % (4)~\textbf{Brightness}--scaled by 1.2 with $+10$ offset.
% % % % This yields $10 \times 25 \times 4 = 1000$ total FPGA inference calls.

% % % % The design is notably lightweight: 3.13\% LUT utilization confirms the suitability of the Artix-7 35T for this pipeline, with substantial headroom for additional processing stages. The use of separable convolution~\cite{sep_conv_fpga}, which reduces the per-pixel MAC count from $O(N^2)$ to $O(N)$, is the primary reason for this low footprint. The eight 128-entry line buffers in the two \texttt{gaussian\_col\_conv} instances are inferred as distributed RAM (96 LUTRAMs), avoiding the need for additional BRAM. BRAM utilization at 18\% accounts for the two 16~KB frame buffers (input and output).

% % % % At 2~Mbaud (10 bits per UART byte), transferring one 128$\times$128 frame takes approximately 82~ms per direction, giving a round-trip of $\sim$164~ms. This is consistent with the measured average of 0.187~s per variant (the difference attributable to host-side serialisation and NCC computation). The convolution pipeline processes all 16,384 pixels at 100~MHz in a few hundred microseconds, making UART the dominant latency bottleneck.

% % % % \textbf{Regions~1 and~2} (near Aristoteles M and N craters) produce stable high scores (means 0.564, 0.531; match rates 89\%, 73\%). These patches are visually characterized by compact crater rims with strong edge contrast whose spatial scale fits well within the 128-pixel field of view, producing repeatable structure-energy maps across augmentations. The score drop in Region~2 relative to Region~1 is partly attributable to the rotated variant: several rotated frames fall just below 0.5 (minimum 0.413), suggesting that the crater structure in Region~2 is less rotation-tolerant.
% % % % \textbf{Regions~3 and~4} achieve the highest scores (means 0.654, 0.634; match rates 99\%, 96\%). Their visually multi-directional edge structure produces rich, spatially distinctive energy maps. Region~4 shows one notable outlier (frame~1, rotated, NCC~=~0.325), likely due to the sinusoidal transform bringing the patch boundary into the convolution, but this does not affect the overall match rate.
% % % % \textbf{Region~0} is the most instructive failure: despite being selected by the texture scorer (high variance + Sobel response at full browse resolution), all 100 variants yield near-zero NCC (max 0.100). The patch is visually flat at 128-pixel scale--an inter-crater floor whose apparent texture at full resolution is fine-grained sub-pixel variation. After downsampling and band-pass filtering, the DoG output is near-uniform and carries no matchable spatial structure.
% % % % \textbf{Regions~5--9} score 0.185--0.279 mean, consistently below the threshold. Their dominant visual structure (wide crater floors; gradual albedo variation) operates at spatial scales that either exceed the 128-pixel patch width or fall outside the kernel passband. The DoG response contains some edge energy but not enough concentrated in distinctive spatial patterns for reliable NCC matching. This is a scale-mismatch between terrain structure and pipeline parameters--not a hardware failure.

% % % % \subsection{Separable Convolution: From $O(N^2)$ to $O(N)$}
% % % % As detailed in Section~\ref{sec:impl}, separable convolution reduces the per-pixel MAC count from $O(N^2)$ to $O(N)$, allowing the complete dual-pipeline front-end to fit in 650 LUTs (3.13\% of the Artix-7 35T) with timing closure at $+2.893$~ns WNS~\cite{sep_conv_fpga}.
% % % % \subsection{Band-Pass Filtering and Scale Limitations}
% % % % The pipeline's matching ability is entirely determined by the spatial information surviving two stages of deliberate reduction: band-pass filtering (DoG) followed by spatial integration (NCC). Any terrain whose dominant structure lies outside the kernel passband at 128$\times$128 pixels will produce a near-uniform energy map regardless of visual richness, yielding a near-zero NCC score.
% % % % The 10 patches were selected to represent diverse highland terrain types--not to cherry-pick easy cases--characterising for which terrain types and scales the pipeline is useful. Compact, high-contrast crater rims (Regions~1--4) align well with the kernel passband. Smooth floors (Region~0), wide-scale structure (Regions~5, 6, 8), and gradually varying terrain (Regions~7, 9) do not.
% % % % \subsection{Architectural Tradeoffs and Threshold Sensitivity}
% % % % The streaming line-buffer approach in \texttt{gaussian\_col\_conv} avoids a second large BRAM but requires sequential single-pass processing: the column stage cannot be restarted mid-frame without flushing all four buffers. UART at 2~Mbaud dominates round-trip latency ($\approx$164~ms); replacing it with SPI, LVDS, or MIPI CSI-2 would reduce transfer time by 1--2 orders of magnitude, enabling video-rate operation. The estimated 95~mW total on-chip power and 25.5\textdegree C estimated junction temperature suggest thermal loading well within bounds, though these values should be validated by hardware measurement.
% % % % The 0.5 NCC threshold is conservative for Regions~1--2, where multiple near-miss variants score 0.47--0.49, while all failing regions score below 0.28 mean. A threshold of 0.45 would improve recall without meaningful precision loss. An adaptive threshold derived from a local structure-energy confidence estimate would further improve robustness across heterogeneous terrain.
% % % % % ============================================================
% % % % \section{Conclusion}
% % % % This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian operator for structure-energy extraction, implemented on a Xilinx Artix-7 xc7a35tcpg236-1 (Basys~3) and evaluated on real Chandrayaan-2 TMC nadir-channel imagery. The design occupies just 3.13\% of available LUTs with timing closure tat $+2.893$~ns WNS and estimated on-chip power of 95~mW (Vivado post-implementation, medium confidence).
% % % % Evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches demonstrates the feasibility of the approach: regions visually characterized by compact crater-rim structure yield 73--99\% match rates, while regions whose dominant spatial structure falls outside the kernel passband at 128$\times$128 pixels do not match reliably. The results identify a clear scale-mismatch limitation of single-scale DoG filtering and demonstrate that hardware band-pass filtering provides a useful structural signal for lunar image matching in texture-rich terrain.
% % % % % ============================================================
% % % % \section{Future Work}
% % % % The most immediate extension is a multi-scale hierarchy to widen the range of matchable terrain types, alongside orientation-aware descriptors to improve robustness on low-texture terrain where NCC is rotation-sensitive. On the hardware side, replacing UART with a high-speed interface (SPI, LVDS, or MIPI CSI-2) would enable video-rate onboard deployment~\cite{fpga_space_vision,space_fpga_cv}, and an adaptive NCC threshold derived from a local structure-energy confidence map would improve classification robustness across heterogeneous terrain. Physical hardware measurements would validate the Vivado post-implementation power and resource estimates.

% % % \begin{abstract}
% % % This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian (DoG) operator for structure-energy extraction in lunar imagery. The proposed system integrates a UART-based streaming interface, two parallel separable convolution stages with distinct smoothing kernels, and on-chip BRAM buffers to enable frame-based processing on a resource-constrained Xilinx Artix-7 FPGA. A hardware-software co-design framework is developed in which the FPGA computes the DoG response while a host system performs normalized cross-correlation (NCC) based template matching on the resulting structure-energy maps. The system is evaluated on a multi-region dataset generated from Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel imagery, comprising 1000 augmented variants across 10 spatially distributed diverse lunar highland patches. Results demonstrate the feasibility of the approach for lunar feature matching: regions visually characterized by compact crater-rim structure yield NCC match rates of 73--99\%, while regions whose dominant spatial structure falls outside the kernel passband at 128$\times$128 pixels do not match reliably. The estimated on-chip power (Vivado post-implementation, medium confidence) is 95~mW at a junction temperature of 25.5\textdegree C, with 3.13\% LUT utilization on the target device.
% % % \end{abstract}

% % % \section{Introduction}
% % % Autonomous vision-based navigation is a critical requirement for planetary exploration missions, particularly for tasks such as terrain relative navigation (TRN), hazard detection and avoidance (HDA), and orbital change detection. Missions such as Chandrayaan-3 have demonstrated the operational need for onboard vision processing under strict real-time and power constraints~\cite{lpsc_ch3_hda}. Embedded FPGA systems have been proposed for space-based vision applications due to their deterministic latency, reconfigurability, and radiation tolerance relative to general-purpose processors~\cite{fpga_space_vision,space_fpga_cv}.
% % % Among gradient-based vision methods, the Difference of Gaussian (DoG) operator is a well-established band-pass filter that suppresses low-frequency intensity variation and high-frequency noise while preserving mid-frequency edge and structural content. In this work, we use the DoG not for keypoint detection but as a lightweight spatial filtering stage: the magnitude of the DoG response serves directly as a structure-energy map, which is then matched via normalized cross-correlation (NCC). This formulation is closer to template-based edge-energy matching than to scale-space extrema detection.
% % % FPGAs provide a suitable platform for accelerating such pipelines due to their inherent spatial parallelism and low power consumption. Deploying a practical FPGA DoG accelerator requires careful co-design of the convolution pipeline, host interface, memory architecture, and evaluation methodology on real imagery.
% % % This work makes the following contributions:
% % % \begin{itemize}
% % %     \item A fully implemented FPGA dual-kernel DoG pipeline on a Xilinx Artix-7 (Basys~3) device using separable 5-tap binomial approximation kernels at two smoothing scales, with runtime-configurable image dimensions and post-implementation resource and power estimation analysis on the Artix-7 device.
% % %     \item A UART-based streaming interface at 2~Mbaud enabling frame transfer between a host PC and the FPGA.
% % %     \item A hardware-software co-design evaluation framework using NCC-based template matching on the host, with quantitative evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches from Chandrayaan-2 TMC data.
% % % \end{itemize}
% % % % ============================================================
% % % \section{Related Work}
% % % Classical descriptors such as SIFT~\cite{lowe2004distinctive}, SURF~\cite{surf2008}, ASIFT~\cite{asift2009}, and ORB~\cite{orb2011} trade invariance against computational cost; for orbital imagery from consistent altitudes, simpler band-pass filtering suffices.

% % % For orbital imagery acquired from consistent altitudes, the primary challenges are illumination variation, minor rotation, and noise rather than large viewpoint change. In this context, DoG-based band-pass filtering provides a hardware-efficient structural signal without requiring full descriptor extraction. The present work uses DoG as a standalone filtering stage--not as part of a SIFT pipeline--and evaluates the structure-energy map directly via NCC.
% % % Feature extraction on FPGA platforms has been extensively studied. Gupta~\textit{et al.}~\cite{fpga_feature_extraction_survey} survey FPGA-based feature extraction architectures. Nakahara and Sato~\cite{dog_fpga_hw} propose a dedicated hardware architecture for DoG calculation in image feature extraction, directly relevant to this work. SIFT-specific FPGA implementations include Yao~\textit{et al.}~\cite{sift_keypoint_fpga} for hardware-efficient keypoint extraction, Reddy~\textit{et al.}~\cite{sift_detector_cta} for a full SIFT detector, and wearable computing FPGA implementations of SIFT~\cite{sift_fpga_wearable}. Parallel FPGA architectures exploit spatial concurrency for higher throughput~\cite{parallel_sift_fpga}, and FPGA-accelerated oriented-FAST features for SLAM demonstrate the viability of hardware gradient pipelines in real-time navigation~\cite{ofast_dog_fpga}. For DoG filtering specifically, Kim~\textit{et al.}~\cite{binary_dog_filter} propose a fast FPGA-optimised implementation. HOG-based descriptors have also been accelerated on FPGA for pedestrian detection~\cite{pure_fpga_hog}, and Park~\textit{et al.}~\cite{dog_retinex_fpga} demonstrate FPGA-based pixel-level image processing for illumination-invariant feature quality--highlighting the broad applicability of hardware image filtering beyond pure feature detection. A key enabler across many of these implementations is separable convolution: Jamali~\textit{et al.}~\cite{sep_conv_fpga} demonstrate energy-efficient parameterized 2-D separable convolution on FPGA, showing significant resource savings over direct 2-D implementations--a result directly borne out in our design.
% % % Vision-based navigation is well established in space missions. Chandrayaan-3 employed a computer vision-based HDA system for autonomous landing site selection~\cite{lpsc_ch3_hda}. Feature matching using Chandrayaan-2 data has been studied in~\cite{ch2_sift_matching}, validating classical descriptor approaches on lunar imagery. Liu~\textit{et al.}~\cite{fpga_space_vision} present a run-time reconfigurable MPSoC-based on-board processor for vision-based space navigation, and Thomas~\textit{et al.}~\cite{space_fpga_cv} adapt robotics vision algorithms for space-rated FPGAs, both highlighting the maturity of FPGA-based vision for space deployment.
% % % The present work complements this literature by providing a low-power, modular FPGA band-pass pipeline evaluated on real Chandrayaan-2 TMC imagery, with explicit analysis of which terrain types benefit from single-scale DoG filtering.

% % % \section{System Architecture}
% % % The proposed system follows a hardware-software co-design philosophy. The FPGA performs all convolution in hardware at deterministic latency, while the host PC manages dataset operations, augmentation, and NCC matching. Fig.~\ref{fig:fpga} illustrates the complete pipeline.
% % % \begin{figure}[htbp]
% % % \centerline{\includegraphics[width=0.48\textwidth]{images/flowchart_diagram_fpga.png}}
% % % \caption{FPGA DoG processing pipeline. Frames are streamed in via UART RX, buffered in input BRAM, processed through two parallel separable convolution paths, and the mapped DoG output is transmitted via UART TX.}
% % % \label{fig:fpga}
% % % \end{figure}
% % % \subsection{FPGA Pipeline}
% % % The FPGA pipeline runs on a Xilinx Artix-7 XC7A35T (Basys~3) at 100~MHz and consists of three stages.
% % % \subsubsection{Input Interface}
% % % A UART receiver at 2~Mbaud (50 clocks/bit at 100~MHz) streams 8-bit grayscale pixels from the host. A 0x55 synchronisation byte marks frame boundaries. Received pixels are stored sequentially into a 16~KB dual-port BRAM (input buffer), supporting up to 128$\times$128 pixels.
% % % \subsubsection{DoG Core}
% % % Two independent separable convolution pipelines operate in parallel on the same input BRAM, sharing a read address bus for cycle-accurate synchronisation. Each pipeline applies a separable 5-tap kernel using:
% % % \begin{itemize}
% % %     \item A horizontal stage using a shift-register tap chain.
% % %     \item A vertical stage using four 128-entry line buffers to maintain a five-row sliding window.
% % % \end{itemize}
% % % The two kernels are 5-tap binomial approximations to Gaussian smoothing at two different smoothing scales:
% % % \begin{equation}
% % %     \mathbf{k}_1 = \tfrac{1}{16}[1,\, 4,\, 6,\, 4,\, 1]
% % %     \label{eq:k1}
% % % \end{equation}
% % % \begin{equation}
% % %     \mathbf{k}_2 = \tfrac{1}{8}[1,\, 2,\, 2,\, 2,\, 1]
% % %     \label{eq:k2}
% % % \end{equation}
% % % These are integer-coefficient binomial approximations, not analytically defined Gaussian kernels with precise $\sigma$ values. $\mathbf{k}_1$ imposes broader smoothing while $\mathbf{k}_2$ imposes less. The structure-energy response is their difference:
% % % \begin{equation}
% % %     \text{DoG}(x, y) = B_1(x,y) - B_2(x,y)
% % %     \label{eq:dog}
% % % \end{equation}
% % % where $B_1$ and $B_2$ are the outputs of the respective blur stages. The result is a signed 9-bit value; its dynamic range is data-dependent.
% % % This design uses the DoG differently from SIFT: rather than searching for signed extrema in a scale-space pyramid, the \emph{magnitude} of $\text{DoG}(x,y)$ is used as a spatial structure-energy map matched via NCC. The system is therefore a hardware band-pass filter whose output encodes local edge and structural energy.
% % % Each pipeline uses a three-state FSM (IDLE $\rightarrow$ READ $\rightarrow$ FLUSH) with a latency compensation counter to discard the initial pipeline fill cycles. Image dimensions are passed as runtime 8-bit parameters (\texttt{img\_width}, \texttt{img\_height}), allowing flexible patch sizes without re-synthesis.
% % % \subsubsection{Mapping and Output Interface}
% % % The signed DoG pixel is mapped to 8-bit unsigned format before transmission:
% % % \begin{equation}
% % %     p_{\text{out}} = 128 + \left\lfloor \frac{\text{DoG}}{2} \right\rfloor
% % %     \label{eq:map}
% % % \end{equation}
% % % This centres the output at 128 (zero response), preserving sign information for the host. Mapped pixels are written to a second 16~KB output BRAM. After processing, the top-level FSM transmits a 0x55 sync byte followed by the 16,384-byte output frame via UART TX.
% % % The top-level controller manages five states:
% % % \begin{enumerate}
% % %     \item \textbf{S\_WAIT\_SYNC}: Idle; waits for 0x55 from the host.
% % %     \item \textbf{S\_RX\_FRAME}: Receives 16,384 pixels into input BRAM.
% % %     \item \textbf{S\_PROCESS}: Asserts \texttt{start\_dog}; waits for \texttt{done}.
% % %     \item \textbf{S\_TX\_SYNC}: Sends 0x55 back to signal readiness.
% % %     \item \textbf{S\_TX\_FRAME}: Streams 16,384 output pixels to the host.
% % % \end{enumerate}
% % % \subsection{Host Processing Pipeline}
% % % The host system (PySerial/OpenCV) handles dataset management, FPGA communication, and NCC matching. For each frame:
% % % \begin{enumerate}
% % %     \item The frame is resized to 128$\times$128; the sync byte value (0x55) is replaced with 0x54 to prevent false synchronisation.
% % %     \item The frame is transmitted to the FPGA; the DoG output is received.
% % %     \item The 128-offset bias is removed to recover the signed response; the absolute value is taken to produce a structure-energy magnitude map; Gaussian smoothing and min-max normalisation to $[0,1]$ are applied; NCC is then computed against the stored template energy map using \texttt{cv2.matchTemplate} with \texttt{TM\_CCOEFF\_NORMED}.
% % %     \item A threshold of 0.5 classifies the result as match or no-match.
% % % \end{enumerate}

% % % \section{Dataset and Methodology}
% % % The dataset is derived from a Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel calibrated browse image with filename \texttt{ch2\_tmc\_ncn\_20240426T0455517041\_b\_brw\_d18.png}, acquired on 26 April 2024 (PDS Product ID: \texttt{ch2\_tmc\_ncn\_20240426T0455517041\_d\_img\_d18}). In the product naming scheme, \texttt{ch2} denotes Chandrayaan-2, \texttt{tmc} is the Terrain Mapping Camera, and \texttt{ncn} designates the nadir-looking camera (distinct from \texttt{ncf} fore and \texttt{nca} aft stereo channels). This strip covers the northern lunar highlands between approximately $41^\circ$N--$61^\circ$N latitude and $26^\circ$E--$28^\circ$E longitude. Data were accessed via the ISRO ISSDC Map Browse portal~\cite{issdc_mapbrowse}, which provides calibrated browse imagery with associated geometry CSV files mapping pixel coordinates to lunar latitude/longitude at approximately 18~m/pixel ground resolution.
% % % The strip is visually characterized as crater-rich highland terrain, with impact features well preserved due to the absence of erosional processes~\cite{nasa_craters}. Patches from this strip tend to contain sharp crater rim edges and shadow boundaries at scales visible in the TMC browse imagery.

% % % \begin{equation}

% % % \textbf{Regions~1 and~2} (near Aristoteles M and N craters) produce stable high scores (means 0.564, 0.531; match rates 89\%, 73\%). These patches are visually characterized by compact crater rims with strong edge contrast whose spatial scale fits well within the 128-pixel field of view, producing repeatable structure-energy maps across augmentations. The score drop in Region~2 relative to Region~1 is partly attributable to the rotated variant: several rotated frames fall just below 0.5 (minimum 0.413), suggesting that the crater structure in Region~2 is less rotation-tolerant.
% % % \textbf{Regions~3 and~4} achieve the highest scores (means 0.654, 0.634; match rates 99\%, 96\%). Their visually multi-directional edge structure produces rich, spatially distinctive energy maps. Region~4 shows one notable outlier (frame~1, rotated, NCC~=~0.325), likely due to the sinusoidal transform bringing the patch boundary into the convolution, but this does not affect the overall match rate.
% % % \textbf{Region~0} is the most instructive failure: despite being selected by the texture scorer (high variance + Sobel response at full browse resolution), all 100 variants yield near-zero NCC (max 0.100). The patch is visually flat at 128-pixel scale--an inter-crater floor whose apparent texture at full resolution is fine-grained sub-pixel variation. After downsampling and band-pass filtering, the DoG output is near-uniform and carries no matchable spatial structure.
% % % \textbf{Regions~5--9} score 0.185--0.279 mean, consistently below the threshold. Their dominant visual structure (wide crater floors; gradual albedo variation) operates at spatial scales that either exceed the 128-pixel patch width or fall outside the kernel passband. The DoG response contains some edge energy but not enough concentrated in distinctive spatial patterns for reliable NCC matching. This is a scale-mismatch between terrain structure and pipeline parameters--not a hardware failure.

% % % \subsection{Separable Convolution: From $O(N^2)$ to $O(N)$}
% % % As detailed in Section~\ref{sec:impl}, separable convolution reduces the per-pixel MAC count from $O(N^2)$ to $O(N)$, allowing the complete dual-pipeline front-end to fit in 650 LUTs (3.13\% of the Artix-7 35T) with timing closure at $+2.893$~ns WNS~\cite{sep_conv_fpga}.
% % % \subsection{Band-Pass Filtering and Scale Limitations}
% % % The pipeline's matching ability is entirely determined by the spatial information surviving two stages of deliberate reduction: band-pass filtering (DoG) followed by spatial integration (NCC). Any terrain whose dominant structure lies outside the kernel passband at 128$\times$128 pixels will produce a near-uniform energy map regardless of visual richness, yielding a near-zero NCC score.
% % % The 10 patches were selected to represent diverse highland terrain types--not to cherry-pick easy cases--characterising for which terrain types and scales the pipeline is useful. Compact, high-contrast crater rims (Regions~1--4) align well with the kernel passband. Smooth floors (Region~0), wide-scale structure (Regions~5, 6, 8), and gradually varying terrain (Regions~7, 9) do not.
% % % \subsection{Architectural Tradeoffs and Threshold Sensitivity}
% % % The streaming line-buffer approach in the column-convolution stage avoids a second large BRAM but requires sequential single-pass processing: the column stage cannot be restarted mid-frame without flushing all four buffers. UART at 2~Mbaud dominates round-trip latency ($\approx$164~ms); replacing it with SPI, LVDS, or MIPI CSI-2 would reduce transfer time by 1--2 orders of magnitude, enabling video-rate operation. The estimated 95~mW total on-chip power and 25.5\textdegree C estimated junction temperature suggest thermal loading well within bounds, though these values should be validated by hardware measurement.
% % % The 0.5 NCC threshold is conservative for Regions~1--2, where multiple near-miss variants score 0.47--0.49, while all failing regions score below 0.28 mean. A threshold of 0.45 would improve recall without meaningful precision loss. An adaptive threshold derived from a local structure-energy confidence estimate would further improve robustness across heterogeneous terrain.

% % % \section{Conclusion}
% % % This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian operator for structure-energy extraction, implemented on a Xilinx Artix-7 xc7a35tcpg236-1 (Basys~3) and evaluated on real Chandrayaan-2 TMC nadir-channel imagery. The design occupies just 3.13\% of available LUTs with timing closure at $+2.893$~ns WNS and estimated on-chip power of 95~mW (Vivado post-implementation, medium confidence).
% % % Evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches demonstrates the feasibility of the approach: regions visually characterized by compact crater-rim structure yield 73--99\% match rates, while regions whose dominant spatial structure falls outside the kernel passband at 128$\times$128 pixels do not match reliably. % % % The most immediate extension is a multi-scale hierarchy to widen the range of matchable terrain types, alongside orientation-aware descriptors to improve robustness on low-texture terrain where NCC is rotation-sensitive. % % \begin{abstract}
% % Autonomous vision for lunar exploration must operate under highly variable terrain and illumination conditions, yet remain within the tight power and resource budgets of embedded spacecraft hardware. This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian (DoG) operator for structure-energy extraction in lunar imagery. The proposed design is motivated by the distinctive visual character of high-latitude lunar terrain: at sub-polar latitudes, low solar elevation angles cast long shadows that enhance crater rim contrast, while the high density of well-preserved impact craters provides rich structural content—conditions that favour gradient-based filtering over full descriptor pipelines. The system integrates a UART-based streaming interface, two parallel separable convolution stages with distinct smoothing kernels, and on-chip BRAM buffers to enable frame-based processing on a resource-constrained Xilinx Artix-7 FPGA. A hardware-software co-design framework is developed in which the FPGA computes the DoG response while a host system performs normalized cross-correlation (NCC) based template matching on the resulting structure-energy maps. The system is evaluated on a multi-region dataset generated from Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel imagery of the northern lunar highlands, comprising 1000 augmented variants across 10 spatially distributed diverse patches. Results demonstrate the feasibility of the approach: regions visually characterised by compact crater-rim structure yield NCC match rates of 73--99\%, while regions whose dominant spatial structure falls outside the kernel passband do not match reliably. The estimated on-chip power is 95~mW with 3.13\% LUT utilization on the target device—confirming the viability of the design as a lightweight complement to heavier descriptors such as SIFT and ORB in resource-constrained lunar mission scenarios.
% % \end{abstract}

% % \section{Introduction}

% % Autonomous vision-based navigation is a critical requirement for planetary exploration missions, particularly for tasks such as terrain relative navigation (TRN), hazard detection and avoidance (HDA), and orbital change detection. Missions such as Chandrayaan-3 have demonstrated the operational need for onboard vision processing under strict real-time and power constraints~\cite{lpsc_ch3_hda}. Embedded FPGA systems have been proposed for space-based vision applications due to their deterministic latency, reconfigurability, and radiation tolerance relative to general-purpose processors~\cite{fpga_space_vision,space_fpga_cv}.

% % The lunar surface presents distinctly different visual characteristics depending on latitude. Equatorial regions receive near-vertical solar illumination that minimises topographic shadow length and reduces the apparent contrast of surface relief features in imagery. Higher-latitude regions, approaching the poles, receive sunlight at increasingly oblique angles close to the horizon; this near-grazing illumination casts long shadows that dramatically enhance the contrast of crater rims, ejecta blankets, and rugged terrain boundaries. This illumination geometry makes gradient-based image processing—and DoG band-pass filtering in particular—naturally well-suited to polar and sub-polar terrain, where shadow boundaries encode structural information at scales accessible to a hardware filter. The high concentration of well-preserved impact craters in polar highlands, shielded from the volcanic resurfacing that dominates equatorial mare regions~\cite{nasa_craters}, further enriches the structural content available for feature matching.

% % Algorithms such as SIFT~\cite{lowe2004distinctive} and ORB~\cite{orb2011} are reliable and widely deployed for feature matching; SIFT, in particular, uses a Difference of Gaussian scale-space as its front-end. However, the computational demands of these methods—multi-scale keypoint detection across several octaves, gradient orientation histograms, and 128-dimensional descriptor computation for SIFT; or binary descriptor chains and centroid-based orientation for ORB—make them impractical for deployment on severely resource-constrained embedded hardware such as a small FPGA intended for a spacecraft payload. The DoG operator itself, stripped of the descriptor and extrema-detection stages, offers a compelling middle ground: it extracts the same mid-frequency structural signal that underlies SIFT's scale-space front-end, at a fraction of the hardware cost. For orbital imagery acquired from consistent altitudes where the dominant challenges are illumination variation, minor rotation, and noise rather than extreme viewpoint change, this lightweight band-pass representation can be matched directly using normalized cross-correlation (NCC) without incurring the full cost of descriptor computation.

% % FPGAs provide a suitable platform for accelerating such pipelines due to their inherent spatial parallelism and low power consumption. Deploying a practical FPGA DoG accelerator requires careful co-design of the convolution pipeline, host interface, memory architecture, and evaluation methodology on real imagery.

% % This work makes the following contributions:
% % \begin{itemize}
% %     \item A fully implemented FPGA dual-kernel DoG pipeline on a Xilinx Artix-7 (Basys~3) device using separable 5-tap binomial approximation kernels at two smoothing scales, with runtime-configurable image dimensions and post-implementation resource and power analysis on the Artix-7 device.
% %     \item A UART-based streaming interface at 2~Mbaud enabling frame transfer between a host PC and the FPGA.
% %     \item A hardware-software co-design evaluation framework using NCC-based template matching on the host, with quantitative evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches from Chandrayaan-2 TMC data—including analysis of which terrain types and illumination conditions the single-scale pipeline handles well.
% % \end{itemize}

% % % ============================================================
% % \section{Related Work}

% % \subsection{Feature Matching Methods and the Lunar Context}

% % Classical feature descriptors trade invariance against computational cost in ways that have direct implications for space hardware. SIFT~\cite{lowe2004distinctive} detects keypoints as extrema in a Difference of Gaussian scale-space and computes a gradient-based descriptor that is robust to scale, rotation, and illumination change. SURF~\cite{surf2008} accelerates this framework with integral images and a Hessian-based detector. ASIFT~\cite{asift2009} extends SIFT to full affine invariance by simulating camera tilt, greatly improving robustness under large viewpoint change at the cost of substantially higher computation. ORB~\cite{orb2011} offers a binary-descriptor alternative based on oriented FAST keypoints and rotated BRIEF, achieving substantially faster runtime than SIFT while sacrificing some scale-change robustness.

% % For orbital lunar imagery acquired from consistent altitudes, the dominant image challenges are not extreme viewpoint change but rather illumination variation, minor rotation, and noise. In this regime, the full machinery of SIFT or ORB is not necessary, and simpler band-pass filtering can provide a sufficient structural signal. Crucially, in high-latitude terrain where low solar elevation enhances crater rim contrast through long shadows, the mid-frequency content captured by a DoG filter is precisely the dominant visual signal available. The present work therefore uses DoG as a standalone filtering stage—not as the front-end of a scale-space extrema detector—and evaluates the resulting structure-energy map directly via NCC, offering a lightweight alternative to full descriptor pipelines for resource-constrained lunar mission hardware.

% % \subsection{FPGA Feature Extraction}

% % Feature extraction on FPGA platforms has been extensively studied. Gupta~\textit{et al.}~\cite{fpga_feature_extraction_survey} survey FPGA-based feature extraction architectures and highlight trade-offs in throughput, resource usage, and precision. Nakahara and Sato~\cite{dog_fpga_hw} propose a dedicated hardware architecture for DoG calculation in image feature extraction, directly relevant to this work. SIFT-specific FPGA implementations include Yao~\textit{et al.}~\cite{sift_keypoint_fpga} for hardware-efficient keypoint extraction and Reddy~\textit{et al.}~\cite{sift_detector_cta} for a full SIFT detector with optimised convolution pipelines. Full-pipeline wearable-computing FPGA implementations of SIFT~\cite{sift_fpga_wearable} and parallel FPGA architectures exploiting spatial concurrency for higher throughput~\cite{parallel_sift_fpga} further demonstrate the maturity of hardware gradient pipelines. For DoG filtering specifically, Kim~\textit{et al.}~\cite{binary_dog_filter} propose a fast FPGA-optimised implementation. HOG-based descriptors have been accelerated on FPGA for real-time pedestrian detection~\cite{pure_fpga_hog}, and Park~\textit{et al.}~\cite{dog_retinex_fpga} demonstrate FPGA-based illumination-invariant image processing—both illustrating the broad applicability of hardware gradient filtering beyond pure feature detection. A key efficiency enabler across many implementations is separable convolution: Jamali~\textit{et al.}~\cite{sep_conv_fpga} demonstrate energy-efficient parameterised 2-D separable convolution on FPGA, showing significant resource savings over direct 2-D implementations—a result directly borne out in our design.

% % \subsection{Vision for Space Applications}

% % Vision-based navigation is well established in space missions. Chandrayaan-3 employed a computer vision-based HDA system for autonomous landing site selection~\cite{lpsc_ch3_hda}, demonstrating that onboard vision is operationally viable under the severe power and compute constraints of a lunar lander. Feature matching using Chandrayaan-2 data has been studied in~\cite{ch2_sift_matching}, validating classical descriptor approaches on real lunar imagery. Liu~\textit{et al.}~\cite{fpga_space_vision} present a run-time reconfigurable MPSoC-based on-board processor for vision-based space navigation, and Thomas~\textit{et al.}~\cite{space_fpga_cv} adapt robotics vision algorithms for space-rated FPGAs, both highlighting the maturity of FPGA-based vision for space deployment. The present work complements this literature by providing a low-power, modular FPGA band-pass pipeline evaluated on real Chandrayaan-2 TMC highland imagery, with explicit analysis of which terrain types—and by extension which latitude-dependent illumination conditions—benefit from single-scale DoG filtering.

% % The FPGA pipeline runs on a Xilinx Artix-7 XC7A35T (Basys~3) at 100~MHz and consists of three stages.

% % \subsubsection{Input Interface}

% % A UART receiver at 2~Mbaud (50 clocks per bit at 100~MHz) streams 8-bit grayscale pixels from the host. A 0x55 synchronisation byte marks frame boundaries. Received pixels are stored sequentially into a 16~KB dual-port BRAM (input buffer), supporting up to 128$\times$128 pixels.

% % \subsubsection{DoG Core}

% % Two independent separable convolution pipelines operate in parallel on the same input BRAM, sharing a read address bus for cycle-accurate synchronisation. Each pipeline applies a separable 5-tap kernel using:
% % \begin{itemize}
% %     \item A horizontal stage using a shift-register tap chain.
% %     \item A vertical stage using four 128-entry line buffers to maintain a five-row sliding window.
% % \end{itemize}

% % The two kernels are 5-tap binomial approximations to Gaussian smoothing at two different smoothing scales:
% % \begin{equation}
% %     \mathbf{k}_1 = \tfrac{1}{16}[1,\, 4,\, 6,\, 4,\, 1]
% %     \label{eq:k1}
% % \end{equation}
% % \begin{equation}
% %     \mathbf{k}_2 = \tfrac{1}{8}[1,\, 2,\, 2,\, 2,\, 1]
% %     \label{eq:k2}
% % \end{equation}

% % These are integer-coefficient binomial approximations, not analytically defined Gaussian kernels with precise $\sigma$ values. $\mathbf{k}_1$ imposes broader smoothing while $\mathbf{k}_2$ imposes less. The structure-energy response is their difference:
% % \begin{equation}
% %     \text{DoG}(x, y) = B_1(x,y) - B_2(x,y)
% %     \label{eq:dog}
% % \end{equation}
% % where $B_1$ and $B_2$ are the outputs of the respective blur stages. The result is a signed 9-bit value; its dynamic range is data-dependent.

% % This design uses the DoG differently from SIFT: rather than searching for signed extrema in a scale-space pyramid, the \emph{magnitude} of $\text{DoG}(x,y)$ is used as a spatial structure-energy map matched via NCC. The system is therefore a hardware band-pass filter whose output encodes local edge and structural energy. For high-latitude lunar terrain where oblique solar illumination produces strong shadow boundaries at crater rims, this structure-energy representation captures the dominant visual signal directly and efficiently.

% % Each pipeline uses a three-state FSM (IDLE $\rightarrow$ READ $\rightarrow$ FLUSH) with a latency compensation counter to discard the initial pipeline fill cycles. Image dimensions are passed as runtime 8-bit parameters (\texttt{img\_width}, \texttt{img\_height}), allowing flexible patch sizes without re-synthesis.

% % \subsubsection{Mapping and Output Interface}

% % The signed DoG pixel is mapped to 8-bit unsigned format before transmission:
% % \begin{equation}
% %     p_{\text{out}} = 128 + \left\lfloor \frac{\text{DoG}}{2} \right\rfloor
% %     \label{eq:map}
% % \end{equation}

% % This centres the output at 128 (zero response), preserving sign information for the host. Mapped pixels are written to a second 16~KB output BRAM. After processing, the top-level FSM transmits a 0x55 sync byte followed by the 16,384-byte output frame via UART TX.

% % The top-level controller manages five states:
% % \begin{enumerate}
% %     \item \textbf{S\_WAIT\_SYNC}: Idle; waits for 0x55 from the host.
% %     \item \textbf{S\_RX\_FRAME}: Receives 16,384 pixels into input BRAM.
% %     \item \textbf{S\_PROCESS}: Asserts \texttt{start\_dog}; waits for \texttt{done}.
% %     \item \textbf{S\_TX\_SYNC}: Sends 0x55 back to signal readiness.
% %     \item \textbf{S\_TX\_FRAME}: Streams 16,384 output pixels to the host.
% % \end{enumerate}

% % \subsection{Host Processing Pipeline}

% % The host system (PySerial/OpenCV) handles dataset management, FPGA communication, and NCC matching. For each frame:
% % \begin{enumerate}
% %     \item The frame is resized to 128$\times$128; the sync byte value (0x55) is replaced with 0x54 to prevent false synchronisation.

At sub-polar latitudes, oblique solar illumination enhances the contrast of crater rim boundaries and topographic relief, producing mid-frequency edge content that a hardware band-pass filter can capture efficiently. The proposed design implements this filtering on a Xilinx Artix-7 XC7A35TCPG236-1 (Basys~3), occupying just 3.13\% of available LUTs with timing closure at $+2.893$~ns WNS and an estimated on-chip power of 95~mW—a footprint that contrasts sharply with the resource requirements of full SIFT or ORB implementations and that is suitable for space-grade embedded deployment.

Regions characterised by compact crater-rim structure—predominantly in the mid-to-high-latitude portion of the strip where shadow contrast is greatest—yield 73--99\% NCC match rates. Regions in the equatorward reaches of the strip, where terrain is smoother and structural content at the 128-pixel scale is weaker, do not match reliably. The results identify a clear scale-mismatch limitation of single-scale DoG filtering and confirm that the design is most effective for the crater-rich, shadow-enhanced terrain characteristic of lunar polar and sub-polar regions.

% \begin{abstract}
% Autonomous vision for lunar exploration must operate under highly variable terrain and illumination conditions, yet remain within the tight power and resource budgets of embedded spacecraft hardware. This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian (DoG) operator for structure-energy extraction in lunar imagery. The proposed design is motivated by the distinctive visual character of high-latitude lunar terrain: at sub-polar latitudes, low solar elevation angles cast long shadows that enhance crater rim contrast, while the high density of well-preserved impact craters provides rich structural content—conditions that favour gradient-based filtering over full descriptor pipelines. The system integrates a UART-based streaming interface, two parallel separable convolution stages with distinct smoothing kernels, and on-chip BRAM buffers to enable frame-based processing on a resource-constrained Xilinx Artix-7 FPGA. A hardware-software co-design framework is developed in which the FPGA computes the DoG response while a host system performs normalized cross-correlation (NCC) based template matching on the resulting structure-energy maps. The system is evaluated on a multi-region dataset generated from Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel imagery of the northern lunar highlands, comprising 1000 augmented variants across 10 spatially distributed diverse patches. Results demonstrate the feasibility of the approach: regions visually characterised by compact crater-rim structure yield NCC match rates of 73--99\%, while regions whose dominant spatial structure falls outside the kernel passband do not match reliably. The estimated on-chip power is 95~mW with 3.13\% LUT utilization on the target device—confirming the viability of the design as a lightweight complement to heavier descriptors such as SIFT and ORB in resource-constrained lunar mission scenarios.
% \end{abstract}

% \section{Introduction}

% Autonomous vision-based navigation is a critical requirement for planetary exploration missions, particularly for tasks such as terrain relative navigation (TRN), hazard detection and avoidance (HDA), and orbital change detection. Missions such as Chandrayaan-3 have demonstrated the operational need for onboard vision processing under strict real-time and power constraints~\cite{lpsc_ch3_hda}. Embedded FPGA systems have been proposed for space-based vision applications due to their deterministic latency, reconfigurability, and radiation tolerance relative to general-purpose processors~\cite{fpga_space_vision,space_fpga_cv}.

% The lunar surface presents distinctly different visual characteristics depending on latitude. Equatorial regions receive near-vertical solar illumination that minimises topographic shadow length and reduces the apparent contrast of surface relief features in imagery. Higher-latitude regions, approaching the poles, receive sunlight at increasingly oblique angles close to the horizon; this near-grazing illumination casts long shadows that dramatically enhance the contrast of crater rims, ejecta blankets, and rugged terrain boundaries. This illumination geometry makes gradient-based image processing—and DoG band-pass filtering in particular—naturally well-suited to polar and sub-polar terrain, where shadow boundaries encode structural information at scales accessible to a hardware filter. The high concentration of well-preserved impact craters in polar highlands, shielded from the volcanic resurfacing that dominates equatorial mare regions~\cite{nasa_craters}, further enriches the structural content available for feature matching.

% Algorithms such as SIFT~\cite{lowe2004distinctive} and ORB~\cite{orb2011} are reliable and widely deployed for feature matching; SIFT, in particular, uses a Difference of Gaussian scale-space as its front-end. However, the computational demands of these methods—multi-scale keypoint detection across several octaves, gradient orientation histograms, and 128-dimensional descriptor computation for SIFT; or binary descriptor chains and centroid-based orientation for ORB—make them impractical for deployment on severely resource-constrained embedded hardware such as a small FPGA intended for a spacecraft payload. The DoG operator itself, stripped of the descriptor and extrema-detection stages, offers a compelling middle ground: it extracts the same mid-frequency structural signal that underlies SIFT's scale-space front-end, at a fraction of the hardware cost. For orbital imagery acquired from consistent altitudes where the dominant challenges are illumination variation, minor rotation, and noise rather than extreme viewpoint change, this lightweight band-pass representation can be matched directly using normalized cross-correlation (NCC) without incurring the full cost of descriptor computation.

% FPGAs provide a suitable platform for accelerating such pipelines due to their inherent spatial parallelism and low power consumption. Deploying a practical FPGA DoG accelerator requires careful co-design of the convolution pipeline, host interface, memory architecture, and evaluation methodology on real imagery.

% This work makes the following contributions:

%     \item A UART-based streaming interface at 2~Mbaud enabling frame transfer between a host PC and the FPGA.
%     \item A hardware-software co-design evaluation framework using NCC-based template matching on the host, with quantitative evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches from Chandrayaan-2 TMC data—including analysis of which terrain types and illumination conditions the single-scale pipeline handles well.

% \section{Related Work}

% \subsection{Feature Matching Methods and the Lunar Context}

% Classical feature descriptors trade invariance against computational cost in ways that have direct implications for space hardware. SIFT~\cite{lowe2004distinctive} detects keypoints as extrema in a Difference of Gaussian scale-space and computes a gradient-based descriptor that is robust to scale, rotation, and illumination change. SURF~\cite{surf2008} accelerates this framework with integral images and a Hessian-based detector. ASIFT~\cite{asift2009} extends SIFT to full affine invariance by simulating camera tilt, greatly improving robustness under large viewpoint change at the cost of substantially higher computation. ORB~\cite{orb2011} offers a binary-descriptor alternative based on oriented FAST keypoints and rotated BRIEF, achieving substantially faster runtime than SIFT while sacrificing some scale-change robustness.

% For orbital lunar imagery acquired from consistent altitudes, the dominant image challenges are not extreme viewpoint change but rather illumination variation, minor rotation, and noise. In this regime, the full machinery of SIFT or ORB is not necessary, and simpler band-pass filtering can provide a sufficient structural signal. Crucially, in high-latitude terrain where low solar elevation enhances crater rim contrast through long shadows, the mid-frequency content captured by a DoG filter is precisely the dominant visual signal available. The present work therefore uses DoG as a standalone filtering stage—not as the front-end of a scale-space extrema detector—and evaluates the resulting structure-energy map directly via NCC, offering a lightweight alternative to full descriptor pipelines for resource-constrained lunar mission hardware.

% \subsection{FPGA Feature Extraction}

% Feature extraction on FPGA platforms has been extensively studied. Gupta~\textit{et al.}~\cite{fpga_feature_extraction_survey} survey FPGA-based feature extraction architectures and highlight trade-offs in throughput, resource usage, and precision. Nakahara and Sato~\cite{dog_fpga_hw} propose a dedicated hardware architecture for DoG calculation in image feature extraction, directly relevant to this work. SIFT-specific FPGA implementations include Yao~\textit{et al.}~\cite{sift_keypoint_fpga} for hardware-efficient keypoint extraction and Reddy~\textit{et al.}~\cite{sift_detector_cta} for a full SIFT detector with optimised convolution pipelines. Full-pipeline wearable-computing FPGA implementations of SIFT~\cite{sift_fpga_wearable} and parallel FPGA architectures exploiting spatial concurrency for higher throughput~\cite{parallel_sift_fpga} further demonstrate the maturity of hardware gradient pipelines. For DoG filtering specifically, Kim~\textit{et al.}~\cite{binary_dog_filter} propose a fast FPGA-optimised implementation. HOG-based descriptors have been accelerated on FPGA for real-time pedestrian detection~\cite{pure_fpga_hog}, and Park~\textit{et al.}~\cite{dog_retinex_fpga} demonstrate FPGA-based illumination-invariant image processing—both illustrating the broad applicability of hardware gradient filtering beyond pure feature detection. A key efficiency enabler across many implementations is separable convolution: Jamali~\textit{et al.}~\cite{sep_conv_fpga} demonstrate energy-efficient parameterised 2-D separable convolution on FPGA, showing significant resource savings over direct 2-D implementations—a result directly borne out in our design.

% \section{Conclusion}

% This paper presents a real-time FPGA-based dual-kernel DoG band-pass filtering pipeline for structure-energy extraction in lunar imagery, motivated by the distinctive visual conditions of high-latitude lunar terrain. At sub-polar latitudes, oblique solar illumination enhances the contrast of crater rim boundaries and topographic relief, producing mid-frequency edge content that a hardware band-pass filter can capture efficiently. The proposed design implements this filtering on a Xilinx Artix-7 XC7A35TCPG236-1 (Basys~3), occupying just 3.13\% of available LUTs with timing closure at $+2.893$~ns WNS and an estimated on-chip power of 95~mW—a footprint that contrasts sharply with the resource requirements of full SIFT or ORB implementations and that is suitable for space-grade embedded deployment.

% Evaluation on 1000 augmented variants across 10 spatially distributed patches from Chandrayaan-2 TMC northern highland imagery demonstrates the feasibility of the approach. Regions characterised by compact crater-rim structure—predominantly in the mid-to-high-latitude portion of the strip where shadow contrast is greatest—yield 73--99\% NCC match rates. Regions in the equatorward reaches of the strip, where terrain is smoother and structural content at the 128-pixel scale is weaker, do not match reliably. The results identify a clear scale-mismatch limitation of single-scale DoG filtering and confirm that the design is most effective for the crater-rich, shadow-enhanced terrain characteristic of lunar polar and sub-polar regions.

% \section{Future Work}

% The most immediate extension is a multi-scale DoG hierarchy to widen the range of matchable terrain types across the equatorial-to-polar spectrum, alongside orientation-aware descriptors to improve robustness on low-texture terrain where NCC is rotation-sensitive. On the hardware side, replacing UART with a high-speed interface (SPI, LVDS, or MIPI CSI-2) would enable video-rate onboard deployment~\cite{fpga_space_vision,space_fpga_cv}, and an adaptive NCC threshold derived from a local structure-energy confidence map—potentially coupled to orbital solar elevation metadata—would improve classification robustness across heterogeneous terrain. Physical hardware measurements would validate the post-implementation power and resource estimates, and evaluation on polar TMC strips at latitudes beyond $70^\circ$N would directly test the hypothesis that oblique illumination benefits DoG-based structural matching.

\begin{abstract}
Autonomous vision for lunar exploration must operate under highly variable terrain and illumination conditions, yet remain within the tight power and resource budgets of embedded spacecraft hardware. This paper presents a real-time FPGA-based dual-kernel band-pass filtering pipeline using the Difference of Gaussian (DoG) operator for structure-energy extraction in lunar imagery. The proposed design is motivated by the distinctive visual character of high-latitude lunar terrain: at sub-polar latitudes, low solar elevation angles cast long shadows that enhance crater rim contrast, while the high density of well-preserved impact craters provides rich structural content—conditions that favour gradient-based filtering over full descriptor pipelines. The system integrates a UART-based streaming interface, two parallel separable convolution stages with distinct smoothing kernels, and on-chip BRAM buffers to enable frame-based processing on a resource-constrained Xilinx Artix-7 FPGA. A hardware-software co-design framework is developed in which the FPGA computes the DoG response while a host system performs normalized cross-correlation (NCC) based template matching on the resulting structure-energy maps. The system is evaluated on a multi-region dataset generated from Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel imagery of the northern lunar highlands, comprising 1000 augmented variants across 10 spatially distributed diverse patches. Results demonstrate the feasibility of the approach: regions visually characterised by compact crater-rim structure yield NCC match rates of 73--99\%, while regions whose dominant spatial structure falls outside the kernel passband do not match reliably. The estimated on-chip power is 95~mW with 3.13\% LUT utilization on the target device—confirming the viability of the design as a lightweight complement to heavier descriptors such as SIFT and ORB in resource-constrained lunar mission scenarios.
\end{abstract}

\section{Introduction}

Autonomous vision-based navigation is a critical requirement for planetary exploration missions, particularly for tasks such as terrain relative navigation (TRN), hazard detection and avoidance (HDA), and orbital change detection. Missions such as Chandrayaan-3 have demonstrated the operational need for onboard vision processing under strict real-time and power constraints~\cite{lpsc_ch3_hda}. Embedded FPGA systems have been proposed for space-based vision applications due to their deterministic latency, reconfigurability, and radiation tolerance relative to general-purpose processors~\cite{fpga_space_vision,space_fpga_cv}.

The lunar surface presents distinctly different visual characteristics depending on latitude. Equatorial regions receive near-vertical solar illumination that minimises topographic shadow length and reduces the apparent contrast of surface relief features in imagery. Higher-latitude regions, approaching the poles, receive sunlight at increasingly oblique angles close to the horizon; this near-grazing illumination casts long shadows that dramatically enhance the contrast of crater rims, ejecta blankets, and rugged terrain boundaries. This illumination geometry makes gradient-based image processing—and DoG band-pass filtering in particular—naturally well-suited to polar and sub-polar terrain, where shadow boundaries encode structural information at scales accessible to a hardware filter. The high concentration of well-preserved impact craters in polar highlands, shielded from the volcanic resurfacing that dominates equatorial mare regions~\cite{nasa_craters}, further enriches the structural content available for feature matching.

Algorithms such as SIFT~\cite{lowe2004distinctive} and ORB~\cite{orb2011} are reliable and widely deployed for feature matching; SIFT, in particular, uses a Difference of Gaussian scale-space as its front-end. However, the computational demands of these methods make them impractical for deployment on severely resource-constrained embedded hardware such as a small FPGA intended for a spacecraft payload. The DoG operator itself, stripped of the descriptor and extrema-detection stages, offers a compelling middle ground: it extracts the same mid-frequency structural signal that underlies SIFT's scale-space front-end, at a fraction of the hardware cost. For orbital imagery acquired from consistent altitudes where the dominant challenges are illumination variation, minor rotation, and noise rather than extreme viewpoint change, this lightweight band-pass representation can be matched directly using normalized cross-correlation (NCC) without incurring the full cost of descriptor computation.

A concrete operational context helps define the pipeline's scope. Consider a lunar orbiter or lander conducting TRN during the orbital or early-descent phase over highland terrain: the spacecraft's nadir camera acquires a $128{\times}128$ grayscale patch; the FPGA computes the DoG structure-energy response in under 1~ms; the response is matched via NCC against a pre-loaded reference energy map derived from mission-planning imagery; a score above threshold supplies a position fix to the onboard navigation filter (e.g., an extended Kalman filter for TRN, or a landmark-confidence signal for HDA), while a below-threshold result withholds the fix rather than injecting a corrupt measurement—triggering a fallback to inertial-only navigation or a safe-hold flag. This pipeline is most appropriate when crater-rim structure is clearly expressed in the imagery at the operational scale: mid-to-high-latitude highland terrain under oblique solar illumination, imaged from a consistent orbital altitude where scale and viewpoint changes are modest. When these conditions do not hold—equatorial smooth terrain, rapidly changing altitude during terminal descent, or large viewpoint tilt—a full descriptor such as SIFT or ORB is required; the DoG pipeline is designed to complement, not replace, those methods for the specific regime where its band-pass response is sufficient. In the present work, NCC is executed on a host PC as an experimental convenience; in a flight implementation, NCC against a pre-stored reference map is a dot-product operation readily implementable in programmable logic or a low-power co-processor at negligible additional resource cost.

This work makes the following contributions:
\begin{itemize}
    \item A fully implemented FPGA dual-kernel DoG pipeline on a Xilinx Artix-7 (Basys~3) device using separable 5-tap binomial approximation kernels at two smoothing scales, with a 2~Mbaud UART streaming interface, runtime-configurable image dimensions, and post-implementation resource and power analysis on the Artix-7 device.
    \item A hardware-software co-design evaluation framework using NCC-based template matching on the host, with quantitative evaluation on 1000 augmented variants across 10 spatially distributed diverse lunar highland patches from Chandrayaan-2 TMC data—including analysis of which terrain types and illumination conditions the single-scale pipeline handles well.
\end{itemize}

\section{Related Work}

\subsection{Feature Matching Methods and the Lunar Context}

Classical feature descriptors trade invariance against computational cost in ways that have direct implications for space hardware. SIFT~\cite{lowe2004distinctive} detects keypoints as extrema in a Difference of Gaussian scale-space and computes a gradient-based descriptor that is robust to scale, rotation, and illumination change. ORB~\cite{orb2011} offers a binary-descriptor alternative based on oriented FAST keypoints and rotated BRIEF, achieving substantially faster runtime than SIFT while sacrificing some scale-change robustness.

For orbital lunar imagery acquired from consistent altitudes, where the dominant challenges are illumination variation and minor rotation rather than extreme viewpoint change, the full machinery of SIFT or ORB is not necessary. The present work therefore uses DoG as a standalone filtering stage—evaluating the resulting structure-energy map directly via NCC—offering a lightweight alternative for resource-constrained lunar mission hardware.

\subsection{FPGA Feature Extraction}

Feature extraction on FPGA platforms has been extensively studied. Gupta~\textit{et al.}~\cite{fpga_feature_extraction_survey} survey FPGA-based feature extraction architectures and highlight trade-offs in throughput, resource usage, and precision. Nakahara and Sato~\cite{dog_fpga_hw} propose a dedicated hardware architecture for DoG calculation in image feature extraction, directly relevant to this work. SIFT-specific FPGA implementations include Yao~\textit{et al.}~\cite{sift_keypoint_fpga} for hardware-efficient keypoint extraction and Reddy~\textit{et al.}~\cite{sift_detector_cta} for a full SIFT detector with optimised convolution pipelines, and parallel FPGA architectures exploiting spatial concurrency for higher throughput~\cite{parallel_sift_fpga} further demonstrate the maturity of hardware gradient pipelines. For DoG filtering specifically, Kim~\textit{et al.}~\cite{binary_dog_filter} propose a fast FPGA-optimised implementation. A key efficiency enabler across many implementations is separable convolution: Jamali~\textit{et al.}~\cite{sep_conv_fpga} demonstrate energy-efficient parameterised 2-D separable convolution on FPGA, showing significant resource savings over direct 2-D implementations—a result directly borne out in our design.

\subsection{Vision for Space Applications}

Vision-based navigation is well established in space missions. Chandrayaan-3 employed a computer vision-based HDA system for autonomous landing site selection~\cite{lpsc_ch3_hda}, demonstrating that onboard vision is operationally viable under the severe power and compute constraints of a lunar lander. Feature matching using Chandrayaan-2 data has been studied in~\cite{ch2_sift_matching}, validating classical descriptor approaches on real lunar imagery. Liu~\textit{et al.}~\cite{fpga_space_vision} present a run-time reconfigurable MPSoC-based on-board processor for vision-based space navigation, and Thomas~\textit{et al.}~\cite{space_fpga_cv} adapt robotics vision algorithms for space-rated FPGAs, both highlighting the maturity of FPGA-based vision for space deployment. The present work complements this literature by providing a low-power, modular FPGA band-pass pipeline evaluated on real Chandrayaan-2 TMC highland imagery, with explicit analysis of which terrain types—and by extension which latitude-dependent illumination conditions—benefit from single-scale DoG filtering.

\section{System Architecture}

The proposed system follows a hardware-software co-design philosophy. The FPGA performs all convolution in hardware at deterministic latency, while the host PC manages dataset operations, augmentation, and NCC matching. Fig.~\ref{fig:fpga} illustrates the complete pipeline.

\begin{figure*}[htbp]
\centerline{\includegraphics[width=\textwidth]{images/flowchart_diagram_fpga.png}}
\caption{FPGA DoG processing pipeline. Frames are streamed in via UART RX, buffered in input BRAM, processed through two parallel separable convolution paths, and the mapped DoG output is transmitted via UART TX.}
\label{fig:fpga}
\end{figure*}

\subsection{FPGA Pipeline}

The FPGA pipeline runs on a Xilinx Artix-7 XC7A35T (Basys~3) at 100~MHz and consists of three stages.

\subsubsection{Input Interface}

A UART receiver at 2~Mbaud (50 clocks per bit at 100~MHz) streams 8-bit grayscale pixels from the host. A 0x55 synchronisation byte marks frame boundaries. Received pixels are stored sequentially into a 16~KB dual-port BRAM (input buffer), supporting up to 128$\times$128 pixels.

\subsubsection{DoG Core}

Two independent separable convolution pipelines operate in parallel on the same input BRAM, sharing a read address bus for cycle-accurate synchronisation. Each pipeline applies a separable 5-tap kernel using:
\begin{itemize}
    \item A horizontal stage using a shift-register tap chain.
    \item A vertical stage using four 128-entry line buffers to maintain a five-row sliding window.
\end{itemize}

The two kernels are 5-tap binomial approximations to Gaussian smoothing at two different smoothing scales:
\begin{equation}
    \mathbf{k}_1 = \tfrac{1}{16}[1,\, 4,\, 6,\, 4,\, 1]
    \label{eq:k1}
\end{equation}
\begin{equation}
    \mathbf{k}_2 = \tfrac{1}{8}[1,\, 2,\, 2,\, 2,\, 1]
    \label{eq:k2}
\end{equation}

These are integer-coefficient binomial approximations, not analytically defined Gaussian kernels with precise $\sigma$ values. $\mathbf{k}_1$ imposes broader smoothing while $\mathbf{k}_2$ imposes less. The structure-energy response is their difference:
\begin{equation}
    \text{DoG}(x, y) = B_1(x,y) - B_2(x,y)
    \label{eq:dog}
\end{equation}
where $B_1$ and $B_2$ are the outputs of the respective blur stages. The result is a signed 9-bit value; its dynamic range is data-dependent.

This design uses the DoG differently from SIFT: rather than searching for signed extrema in a scale-space pyramid, the \emph{magnitude} of $\text{DoG}(x,y)$ is used as a spatial structure-energy map matched via NCC. The system is therefore a hardware band-pass filter whose output encodes local edge and structural energy. For high-latitude lunar terrain where oblique solar illumination produces strong shadow boundaries at crater rims, this structure-energy representation captures the dominant visual signal directly and efficiently.

Each pipeline uses a three-state FSM (IDLE $\rightarrow$ READ $\rightarrow$ FLUSH) with a latency compensation counter to discard the initial pipeline fill cycles. Image dimensions are passed as runtime 8-bit parameters (\texttt{img\_width}, \texttt{img\_height}), allowing flexible patch sizes without re-synthesis.

\subsubsection{Mapping and Output Interface}

The signed DoG pixel is mapped to 8-bit unsigned format before transmission:
\begin{equation}
    p_{\text{out}} = 128 + \left\lfloor \frac{\text{DoG}}{2} \right\rfloor
    \label{eq:map}
\end{equation}

This centres the output at 128 (zero response), preserving sign information for the host. Mapped pixels are written to a second 16~KB output BRAM. After processing, the top-level FSM transmits a 0x55 sync byte followed by the 16,384-byte output frame via UART TX.

The top-level controller manages five states:
\begin{enumerate}
    \item \textbf{S\_WAIT\_SYNC}: Idle; waits for 0x55 from the host.
    \item \textbf{S\_RX\_FRAME}: Receives 16,384 pixels into input BRAM.
    \item \textbf{S\_PROCESS}: Asserts \texttt{start\_dog}; waits for \texttt{done}.
    \item \textbf{S\_TX\_SYNC}: Sends 0x55 back to signal readiness.
    \item \textbf{S\_TX\_FRAME}: Streams 16,384 output pixels to the host.
\end{enumerate}

\subsection{Host Processing Pipeline}

The host system (PySerial/OpenCV) handles dataset management, FPGA communication, and NCC matching. For each frame:
\begin{enumerate}
    \item The frame is resized to 128$\times$128; the sync byte value (0x55) is replaced with 0x54 to prevent false synchronisation.
    \item The frame is transmitted to the FPGA; the DoG output is received.
    \item The 128-offset bias is removed to recover the signed response; the absolute value is taken to produce a structure-energy magnitude map; Gaussian smoothing and min-max normalisation to $[0,1]$ are applied; NCC is then computed against the stored template energy map using \texttt{cv2.matchTemplate} with \texttt{TM\_CCOEFF\_NORMED}.
    \item A threshold of 0.5 classifies the result as match or no-match.
\end{enumerate}

\section{Dataset and Methodology}

\subsection{Lunar Terrain Context and Image Source}

The dataset is derived from a Chandrayaan-2 Terrain Mapping Camera (TMC) nadir-channel calibrated browse image of the northern lunar highlands, accessed via the ISRO ISSDC Map Browse portal~\cite{issdc_mapbrowse}. The strip covers the Aristoteles crater neighbourhood between approximately $41^\circ$N--$61^\circ$N latitude and $26^\circ$E--$28^\circ$E longitude at approximately 18~m/pixel ground resolution.

\subsection{Patch Extraction and Geo-referencing}

Ten 128$\times$128 pixel patches are extracted using a texture scoring criterion combining pixel variance and mean absolute Sobel gradient magnitude, with a minimum spatial separation of 150 pixels between patch centres. Geo-referencing uses the accompanying geometry CSV file to map pixel coordinates to lunar latitude/longitude.

\subsection{Augmentation Protocol}

For each region, one template patch (preprocessed with Gaussian blur and min-max normalisation) and 25 transformed frames are generated using sinusoidal rigid-body transforms:
\begin{equation}
    \theta(t) = 10^\circ \sin(2\pi t),\quad s(t) = 1 + 0.05\cos(2\pi t),\quad t = \tfrac{f}{25}
\end{equation}
where $\theta$ and $s$ are rotation angle and scale, $f \in [0,24]$ is the frame index. Stochastic Gaussian blur (probability 0.3) and additive noise (probability 0.3, $\sigma=3$) are applied for realism.

Each of the 25 frames per region is evaluated under four host-side augmentation variants:
(1)~\textbf{Original}--frame as generated;
(2)~\textbf{Noise}--Gaussian noise ($\sigma=10$) added;
(3)~\textbf{Rotated}--additional 8\textdegree\ rotation;
(4)~\textbf{Brightness}--scaled by 1.2 with $+10$ offset.
This yields $10 \times 25 \times 4 = 1000$ total FPGA inference calls.

Crater rim shadows appear with high tonal contrast, producing repeatable structure-energy maps across augmentations. The score drop in Region~2 relative to Region~1 is partly attributable to the rotated variant, suggesting that the crater structure in Region~2 is less rotation-tolerant.

\textbf{Regions~3 and~4} achieve the highest scores (means 0.654, 0.634; match rates 99\%, 96\%). Region~3 at $60^\circ$N is among the highest-latitude patches and shows the rugged multi-directional edge structure consistent with densely cratered poleward terrain under low solar elevation. Its rich, spatially distinctive energy maps drive the highest match rate in the dataset. Region~4 shows one notable outlier (frame~1, rotated, NCC~=~0.325), likely due to the sinusoidal transform bringing the patch boundary into the convolution, but this does not affect the overall match rate.

\textbf{Region~0} is the most instructive failure: despite being selected by the texture scorer, all 100 variants yield near-zero NCC (max 0.100). At $41.8^\circ$N—the equatorward edge of the strip—this patch sits in a relatively flat inter-crater floor. Its apparent texture at full browse resolution is fine-grained sub-pixel variation that disappears after downsampling; after band-pass filtering, the DoG output is near-uniform. This is consistent with the expectation that equatorial-facing terrain, with shorter shadow lengths and less pronounced crater relief at the chosen scale, produces weaker structural signals than highland terrain at higher latitudes.

\textbf{Regions~5--9} score 0.185--0.279 mean, consistently below the threshold. Their dominant visual structure—wide crater floors, gradual albedo variation, smooth plains—operates at spatial scales that either exceed the 128-pixel patch width or fall outside the kernel passband. The DoG response contains some edge energy but not enough concentrated in distinctive spatial patterns for reliable NCC matching. This is a scale-mismatch between terrain structure and pipeline parameters—not a hardware failure. Notably, Regions~7 and~0 (both near $41^\circ$N) are the smoothest-performing patches, reinforcing the observation that the equatorward reaches of the strip provide less structural content for this filter than the poleward reaches.

\subsection{Band-Pass Filtering, Illumination, and Scale}

These results confirm the physical motivation: at higher latitudes, oblique solar illumination enhances crater rim shadow contrast, producing mid-frequency edge energy that the DoG band-pass isolates reliably; at lower latitudes and over smooth terrain, the energy map is near-uniform regardless of visual richness, and NCC fails. The 10 patches were selected to represent diverse highland terrain types—not to cherry-pick easy cases—specifically to characterise for which terrain types and scales the pipeline is useful and where a more capable descriptor such as SIFT or ORB would be needed.

\subsection{Architectural Tradeoffs and Threshold Sensitivity}

The streaming line-buffer approach in the column-convolution stage avoids a second large BRAM but requires sequential single-pass processing: the column stage cannot be restarted mid-frame without flushing all four line buffers. UART at 2~Mbaud dominates round-trip latency ($\approx$164~ms); replacing it with SPI, LVDS, or MIPI CSI-2 would reduce transfer time by 1--2 orders of magnitude, enabling video-rate operation. The estimated 95~mW total on-chip power and 25.5\textdegree C estimated junction temperature suggest thermal loading well within bounds, though these values should be validated by hardware measurement.

The 0.5 NCC threshold is conservative for Regions~1--2, where multiple near-miss variants score 0.47--0.49, while all failing regions score below 0.28 mean. A threshold of 0.45 would improve recall without meaningful precision loss. An adaptive threshold derived from a local structure-energy confidence estimate—potentially informed by a solar elevation proxy—would further improve robustness across heterogeneous terrain.

\section{Conclusion}

This paper presents a real-time FPGA-based dual-kernel DoG band-pass filtering pipeline for structure-energy extraction in lunar imagery. The design occupies 3.13\% of available LUTs on a Xilinx Artix-7 XC7A35TCPG236-1 (Basys~3) with timing closure at $+2.893$~ns WNS and an estimated on-chip power of 95~mW—a footprint suitable for space-grade embedded deployment and far below the resource requirements of full SIFT or ORB implementations. Evaluation on 1000 augmented variants across 10 spatially distributed patches from Chandrayaan-2 TMC northern highland imagery demonstrates the feasibility of the approach: mid-to-high-latitude regions characterised by compact crater-rim structure yield 73--99\% NCC match rates, while equatorward smooth terrain does not match reliably. The results confirm that the pipeline is most effective precisely where the physics favour it—crater-rich, shadow-enhanced terrain at sub-polar latitudes—and identify single-scale DoG filtering as the primary limitation for broader terrain coverage.

Extensions include a multi-scale DoG hierarchy to widen the matchable terrain range, orientation-aware descriptors to improve rotation robustness, and replacement of UART with a high-speed interface (SPI, LVDS, or MIPI CSI-2) for video-rate onboard deployment~\cite{fpga_space_vision,space_fpga_cv}. Physical hardware measurements would validate the post-implementation power estimates, and evaluation on polar TMC strips beyond $70^\circ$N would directly test whether more oblique illumination further benefits DoG-based structural matching.
